# 溯源 Agent（review）缺陷记录

> 日期：2026-08-28
> 场景：2026-07-16 存储狙击日切片溯源测试（`build_iterate_cases.py --agent review --date 2026-07-16` + 基线回放）
> 状态：缺陷待修（已确认修复方向：异动板块定向搜索增强）

## 背景

2026-07-16 韩国检方突击搜查澜起科技/瑞萨/Rambus 三家内存接口芯片厂商（反垄断调查），A 股存储板块崩盘（澜起 A 股 -16.44%，上证 -1.85%、创业板 -2.95%）。用户希望测试：按平时溯源流程，review agent 能否从丛杂信息中溯源到"存储狙击"这个主因。

## 测试结果：溯源止步于板块层，未到事件层

review agent 基线输出（切片为平时流程生成）：
```
确认的市场现象：broad_decline（沪深核心指数同步下跌）
归因结论：证据不足，未确认主因。
候选解释：global_risk_liquidity（weak）
未解问题：无具体产业事件，半导体板块下跌原因不明。
```

**已识别**：SECTOR_LIST 含存储芯片/中芯国际概念/先进封装/第三代半导体/芯片概念（板块层面命中半导体链）。
**未命中**：未归因到"韩国检方突击搜查"事件。

结论：**不是 LLM 归因能力不足，是证据采集盲区**——切片里根本没有该事件的新闻证据。

## 缺陷 1：快照搜索 query 是固定通用词，不针对异动板块定向检索

**根因**（`market_trace_snapshot.py`）：
```python
tavily_query_1 = f"{report_date} 中国 资本市场 政策 产业 公告"
tavily_query_2 = f"{report_date} 全球股市 利率 汇率 大宗商品 地缘风险"
```
固定 query 搜到的是宏观/市场展望类新闻（深圳金融政策、创业板改革、外汇数据等），**不含具体产业事件**。当日半导体/存储板块领跌这一关键异动，没有任何定向检索（如"7月16日 存储 半导体 暴跌 原因"）。

**影响**：
- 溯源 agent 只能基于市场数据（板块涨跌/资金流）推断到板块层，无法获得事件级证据
- 历史回补场景尤其严重：财联社电报历史为空 + 事件库无记录时，通用搜索成为唯一证据源且搜不到具体事件

**修复方向**（已确认，待实现）：
- 快照构建时，若现象检测识别到异动板块（如领跌板块 Top N），追加定向搜索 query：`{date} {板块名} 暴跌|大涨 原因`，并入 sources
- 定向搜索失败不阻断快照（降级为现状）

## 缺陷 2：历史回补切片的事件证据源天然缺失

**根因**：
- 财联社电报接口 `telegraph?date=2026-07-16` 返回空（历史电报不保留）
- 事件库（event_scrape/stock_trace）7 月无记录（异动监控当时未上线或未触发）
- 导致历史切片只能靠通用搜索，证据质量低于当日实时链路

**影响**：`--date` 历史回补产出的切片在事件证据上系统性偏弱，评估结果不能代表当日真实溯源能力。

**修复方向**：
- 定向搜索增强（缺陷 1）是主要缓解
- 远期：财联社电报历史落库（按日归档），或事件库补采历史日

## 缺陷 3：溯源报告对"证据不足"的呈现可操作性弱

**现象**：基线输出"证据不足，未确认主因""半导体板块下跌原因不明"，未给出"若要确认主因，需要哪类证据"的明确指引。

**影响**：对用户/迭代框架而言，缺陷定位停留在"缺证据"，未闭环到"缺什么证据 → 如何采集"。

**修复方向**（低优先级）：
- review 输出在"未解问题"处给出可执行的证据采集建议（如"需检索存储/半导体板块当日重大事件新闻"），为迭代 agent 的变体生成提供更明确的改进信号
