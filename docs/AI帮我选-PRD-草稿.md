## 1. 背景与目标

### 1.1 现状一句话

「选股」主 Tab 下有**四个子 Tab**：`AI帮我选 / 趋势股 / 机构热门股 / 业绩预测`。它们各自独立、能出结论，**但彼此之间没有任何统一的口径层**，也**没有任何用户维度的记录**。

### 1.2 现状的结构性问题（本次调研确认）

| # | 问题 | 证据 |
| --- | --- | --- |
| 1 | **四个子 Tab 是四套异构链路**——不同数据表、不同生成时点、不同字段结构 | 见 4.3 与 4.5 |
| 2 | **子 Tab 硬编码在前端**，后端无「流派」字段 | `StockContent.vue:32` 写死四个 key/label；`ai_stock_selection_*` 三表无 strategy 字段 |
| 3 | **推荐结果全用户共享，无 `user_id`** | 四张源表 DDL 里均无用户字段 |
| 4 | **无埋点、无反馈入口** | 选股页全文无上报代码；唯一用户动作是「AI帮我选」的"加自选" |
| 5 | **无后台审核系统** | 选股相关管理动作只有内部 token 触发重跑，无审核/配置端点，同仓库也无后台前端 |
| 6 | **前端有多处未接线的半成品** | 业绩预测的 `reports` 视图不可达；分页 `loadMore` 未绑定任何触发；搜索/排序状态已定义但 UI 未渲染；机构热门股无加载态与错误态 |
| 7 | **「AI帮我选」的排序被前端覆盖** | 后端返回 `rank`，前端却按当日涨跌幅降序重排（`AiPickContent.vue` `byChangePctDesc`），**实际展示的不是 AI 排名** |
| 8 | 用户偏好不被记忆 | 子 Tab 选中态是组件内 `ref`，默认恒为 `ai`，不落存储 |

### 1.3 目标（可检验）

| # | 目标 | 怎么算达成 |
| --- | --- | --- |
| G1 | 流派从"前端硬编码"变为"可枚举、可配置、可扩展" | 新增/调整一个流派不需要改前端代码 |
| G2 | 用户能表达并切换自己的选股口径，且被记住 | 用户选择落库，下次进入沿用 |
| G3 | 每一次推荐都能收到**可归因**的反馈 | 反馈带原因标签，可按流派聚合出"哪类理由不成立" |
| G4 | 用户的方法论能进得来并沉淀 | 提交的流派经 agent 初审 + 人工复核后可上架 |
| G5 | 沉淀出可用的用户画像 | 可导出"用户 → 流派偏好"标签 |

## 2. 决策前提：【已定】现有四个子 Tab 就是流派

**这是一条已确认的前提，它把本需求从"新增"变成了"重构 + 完善 + 扩展"。**

也就是说：**我们不是要发明"流派"，而是要给已经存在的四个流派补上一个统一的流派层。**

由此带来两个必须做的事：

1. **把四个硬编码子 Tab 抽成流派注册表**（否则 DIY 和扩展无从谈起）
2. **在数据层走"渐进收敛"**：本期薄封装，中期把可收敛的维度收进统一引擎

### 2.1 收敛路径【已定：渐进】

| 路径 | 做法 | 代价 | 结论 |
| --- | --- | --- | --- |
| **A 薄封装** | 保留四套异构数据源，流派只做一层**注册表**（声明数据来源、口径说明、产出字段、刷新策略）。DIY 只能是已有信号的组合 | 低成本、快上线；但流派能力受限于已有信号 | 本期起点 |
| **B 统一引擎** | 把四条链路收敛成同一套「候选池 → 多维打分 → 选出 TopN」引擎，每个流派只是一组筛选条件与权重 | 高成本；但它才是 DIY 真正的天花板 | 中期目标 |
| **渐进** | A 起步，逐步把能收敛的维度收进统一引擎 | 兼顾 | ✅ **已定** |

### 2.2 为什么"渐进"可行——一个现成的落点

**「AI帮我选」的候选池已经携带多维信号：`trend / institution / forecast / market / technical / capitalFlow / events / riskFlags`**（存于 `ai_stock_selection_candidates.candidate_payload`）。

但当前它是**硬编码权重**：按名次线性给分（`TOP_PER_SOURCE + 1 - rank`，`TOP_PER_SOURCE = 10`）、同行业最多 3 只，规则全部写死在代码中。

> 也就是说：**"流派可配置化"的落点其实已经存在**——流派 = 对这些已有维度的一组筛选条件与权重。本期只需把这组硬编码参数**外化为流派配置**，就能让 DIY 在低成本下成立。

## 3. 概念定义：流派是选股口径，不是交易策略

| | **选股口径（流派）** | 交易策略 |
| --- | --- | --- |
| 回答的问题 | 买**什么** | **怎么**买 |
| 典型内容 | 价值 / 成长 / 动量 / 事件驱动 / 机构跟风 / 趋势 | 仓位几成、持有多久、止盈止损、分批 or 网格 |
| 本功能归属 | ✅ 本文档范围 | ❌ 不属于 |

**为什么不做交易策略**

1. **保持低门槛**：让用户预设交易策略，等于把研究成本重新加回来，与"零成本拿到推荐"的定位冲突。
2. **保持归因清晰**：若用户自定义交易策略，收益该归功于"AI 选股"还是"用户的策略"就说不清——而这恰是模拟炒股大赛要反哺的核心命题。
3. **与大赛口径一致**：大赛的选股来源统一来自本功能，不掺入用户自定义策略。

**流派的正确作用范围**：**效力止于"池子里有哪些票"**，不约束用户的买卖动作。

> 顺序上还有一条规矩：若将来要做"交易策略"，正确次序是**先跑大量数据 → 从行为里观察出打法 → 再推荐给同类用户**，而不是先让用户选打法。观察在前，推荐在后。

### 4.5 数据与接口

| 子 Tab | 接口 | 源表 | 生成方式 |
| --- | --- | --- | --- |
| AI帮我选 | `GET /api/ai-stock-selection/latest` | `ai_stock_selection_runs / _candidates / _results` | **cron 交易日 08:15**（依赖 08:10 的机构热门股检测）→ 六榜聚合候选 → 富化 → **千问 LLM 选出 Top10** → 落库 → **08:20 定版** |

| 机构热门股 | `GET /api/cn/institution-research/history?trading_days=3&min_resonance=2` | `institution_research_history` | cron 交易日多时点（**07:50 / 08:10** / 09:30 / 10:30 / 11:30 / 13:30 / 14:30 / 15:05）检测 |
| 业绩预测 | `GET /api/cn/stocks/profit-forecast` | `earnings_forecast`（+ `_versions`） | cron 每日 00:00 更新 |

**「AI帮我选」关键字段**（`GET /latest` 返回）

- 批次级：`runId` / `tradeDate` / `status('generating'|'ready'|'failed')` / `candidateCount` / `dataAsOf` / `generatedAt` / `summary` / `model` / **`promptVersion`（口径版本，常量 `ai-stock-selection.v1`）** / `errorMessage`
- 个股级：`rank` / `symbol` / `name` / `industry` / `recommendationLevel('较高'|'中等'|'关注')` / **`reason: string[]`** / `riskTip` / `price` / `changePct` / `sparkline: number[]`

> 注意：`candidate_payload` 里实际上还有 `trend / institution / forecast / market / technical / capitalFlow / events / riskFlags` 八个维度，但 `/latest` **只透出** `market.price/changePct` 与 `technical.sparkline`，其余维度未对外暴露。

**权限与去重**：`/generate` 需内部 token（普通用户 403）；`activeRunId` 保证同一时刻只有一个 run。

### 4.6 「选股」域不存在的东西（确认清单）

- ❌ 没有任何 `strategy / mode / style / 流派 / 策略` 字段（`wind_leader_push_history.strategy_name` 属风口龙头推送，与本域无关）
- ❌ 没有 `user_id`，推荐全用户共享
- ❌ 没有用户查看/点击/采纳/收藏 的行为表
- ❌ 没有选股专用后台管理/审核接口，也没有同仓库后台前端
- ❌ 没有埋点
- ❌ 没有前端缓存（"避免旧快照"靠切 Tab 时 `refresh()` 重拉）

### 4.7 生成时点与盘前口径（方案 B）**【已定】**

**问题**：原设计在**交易日 09:40** 生成 Top10，但 A 股 09:30 开盘，而模拟炒股大赛的「盘前」时段要在开盘前给用户今日池——**原时点根本赶不上盘前**。

**方案 B**：把机构热门股检测提前，并把「AI 帮我选」挪到盘前一次定版。

| 时间 | 任务 | 变化 |
| --- | --- | --- |
| 00:00 | 业绩预测 / 业绩报告更新 | 不变 |
| 02:00 | 趋势股批量评分 | 不变 |
| 03:00 | 风口龙头分析 | 不变 |
| **07:50** | 机构热门股检测（盘前第 1 次 · 隔夜研报与新闻） | **新增** |
| **08:10** | 机构热门股检测（盘前第 2 次 · 早间研报） | **新增** |
| **08:15** | **AI 帮我选生成**（依赖 08:10 的共振结果） | **09:40 → 08:15** |
| **08:20** | 状态置 `ready`（**当日定版**） | 新增 |
| **08:30** | 大赛「盘前」时段开启 | **08:00 → 08:30** |
| 09:30 / 10:30 / 11:30 / 13:30 / 14:30 / 15:05 | 机构热门股检测（盘中 / 盘后） | 不变（09:30 起不再触发选股重算） |

**三条必须遵循的口径**

1. **一天只生成一次**：08:15 定版后当天不再重算。这恰好与大赛「开局锁定、局内不变」同构——上游定版，下游锁定，两边不会打架。
2. **失败重试与降级**：08:25 重试一次；仍失败则置 `failed`，前端显示「今日 AI 选股生成失败」，大赛当天**不开新局**。禁止用上一交易日的池子冒充"今日池"。
3. **盘前价格口径**：08:15 尚未开盘，`price` / `changePct` 只能取**上一交易日收盘价与涨跌幅**。前端必须显式标注「**昨收**」，禁止显示成当日涨跌。

## 5. 核心模型（改造后新增）

| 模型 | 定义 |
| --- | --- |
| **流派注册表** | 一条流派 = `{ id, 名称, 一句话说明, 数据来源, 口径定义, 产出字段, 刷新策略, 状态, 口径版本 }`。四份硬编码子 Tab 收敛于此 |
| **流派配置（口径）** | 该流派在已有信号维度上的**筛选条件与权重**（例如：在 `trend` 维度取前 N、`institution` 维度加权 W） |
| **用户流派档案** | 用户当前选中的流派 + 变更历史 + 是否完成首次引导 + 自我描述（DIY 提交内容） |
| **DIY 提交单** | 用户提交的流派：文本描述 + **可映射性判定** + 人工复核结论 + 最终归属 |
| **反馈记录** | 一次推荐结果的满意度 + 原因标签 + 关联批次 |
| **推荐批次** | 一次 Top10 生成结果（`ai_stock_selection_runs`），是反馈与画像的挂载点 |

**状态流转**

```
流派：       草稿 → 待审核 → 已上架（口径版本 +1，历史需回算）→ 已下线（不可删除）
DIY 提交单： 已提交 → agent 初审中 → 待人工复核 → 已上架 / 已归入默认 → 已通知用户
用户流派档案：未建档 → 已引导（选中 or 跳过）→ 已记住（后续可切换）
```

## 6. 功能需求

### FR-01 流派注册表与选择

**目的**：让流派从"前端硬编码"变为"可配置、可扩展"，同时让用户用最低成本表达自己想要哪种选法。

**规则**

- 四个现有子 Tab **收敛为流派注册表**，前端不再硬编码条目 **【已定】**
- 流派以**一行胶囊按钮**呈现，**沿用现有子 Tab 条的视觉规范**（见 4.2），不重新发明交互 **【已定】**
- **首次引导：【已定：胶囊 + 首次引导 两者都做】** 详见 6.1
- **默认流派**：跳过引导或未建档时，默认停在「AI 帮我选」 **【已定】**
- **记住用户选择**：选择落库，下次进入沿用（现状不记忆）**【已定】**
- 流派**只影响选股口径**，不限制用户的买卖动作 **【已定】**

#### 6.1 首次引导（本轮新增，按 #4）

| 项 | 规格 |
| --- | --- |
| 触发条件 | 用户**尚无流派档案**时，首次进入「选股」主 Tab |
| 频次 | **只出现一次**；出现后即写入档案（无论是否选择） |
| 形态 | 底部弹层 / 引导卡，列出四个流派 + 一句话说明（复用注册表里的 `说明` 字段） |
| 是否必须选 | **可跳过**。跳过则落默认「AI 帮我选」，档案标记为 `skipped` |
| 生效时机 | 选完立即生效并记住，不需要二次确认 |
| 后续进入 | 不再弹引导，直接落在上次选中的流派 |

> 设计意图：**一次性把"这里有几种选法"讲清楚**，避免用户永远只用第一个 Tab；同时用"可跳过"保证零门槛路径不被阻塞。

### FR-02 流派内容展示

**规则**

- 每个流派需在注册表中声明**自己的产出字段与展示形态**（异构是现状，本期不强行统一）
- 结果页需能回答"这批票是按什么口径筛出来的"——每只标的标注**所属流派**
- 结果一旦生成即**固化**，不因后续口径变更而改写（供大赛等消费方锁定使用）
- **修正现状缺陷**：「AI帮我选」的展示排序应与后端 `rank` 一致，不再按当日涨跌幅重排 **【已定】**
- **盘前价格标注**：08:15 生成时尚未开盘，`price` / `changePct` 取**昨收**，结果页必须显式标注「昨收」 **【已定，见 4.7】**

### FR-03 满意度反馈（可归因）**【已定】**

**目的**：把"情绪"变成"可执行的修改项"，并为口径迭代提供证据。

**规则**

- **粒度**：P0 做"整组推荐"粒度；单只标的粒度放 P1 **【已定】**
- **满意**：轻量，不追问
- **不满意**：**必选**一个原因，四个选项 **【已定】**
  - `标的不好` / `推荐理由不成立` / `时机不对` / `这类票我不想要`
- 全部记录 `user_id` + 流派 + 推荐批次 + 时间

**为什么必须可归因**：只有一条"不满意"，系统不知道该改什么。原因分布本身就是"口径该往哪调"的证据——例如 70% 选「推荐理由不成立」，该改的是理由生成，而不是选股逻辑。

### FR-04 DIY 提交流派

**目的**：让用户的方法论进得来，同时采集用户画像。

**提交内容**：流派名称 · 怎么选股（自由文本，必填） · 可选举例说明

**⭐ 关键机制：可映射性判定**

> DIY 能不能低成本上架，取决于**用户的描述能否落到已有的信号维度上**。因此 agent 初审**必须输出这个判定**，而不是只判断"像不像已有流派"。

| 判定结果 | 含义 | 处理 |
| --- | --- | --- |
| **可映射** | 描述能落到已有维度（`trend / institution / forecast / capitalFlow / events / market / technical / riskFlags`）的组合上 | 可上架——本质是生成一组新的**筛选条件与权重**，无需新数据源 |
| **不可映射** | 需要当前不存在的数据源或口径 | 标记「需开发」，**不进本期上架队列**，仅作为需求线索沉淀 |

**判定与审核分工【已定：agent 初审输出 + 人工复核确认】**

```
用户提交
   ↓
agent 初审：① 能否归入已有流派？ ② 若不能，能否映射到已有信号维度？
   ├─ 可归入 → 直接归入该流派 + 保留用户自我描述（画像数据到手）
   ├─ 可映射 → 输出「映射到哪些维度 + 大致筛选/加权方式」→ 待人工复核
   └─ 不可映射 → 输出缺口说明（缺什么数据源）→ 标记「需开发」
              ↓
           后台人工复核（本期做最小形态：待审列表 + 通过/驳回 + 归类）【已定】
              ├─ 通过 → 上架为新流派（口径版本 +1，需回算）；决策权：产品/组长 1 人拍板【已定】
              └─ 不通过 → 归入最接近的默认流派，并告知用户
   ↓
通知用户结果
```

**必须的约束**

| # | 约束 | 理由 |
| --- | --- | --- |
| 1 | agent 初审**必须输出**可映射性判定与映射方式 | 否则人工复核没有依据，只能重读一遍用户的话 |
| 2 | 上架 **= 口径变更**，必须走版本号 + 历史回算，不可直接生效 | 否则历史结果与往后结果不可比 |
| 3 | 已上架流派**不可删除**，只能下线 | 否则历史数据无法解释 |
| 4 | 提交需有**频次限制**与重复检测 | 防滥用、防与现有流派高度重复 |
| 5 | 用户描述中**不得出现收益承诺类表述** | 合规 |
| 6 | 审核结果**必须通知用户** | 否则用户不会再提交第二次 |
| 7 | **用户不可修改 / 下线自己提交的流派，只能提交一次** **【已定】** | 治理成本最低；避免"已上架流派不可删除"的冲突 |

### FR-05 口径版本与回算

- 流派集合（新增 / 下线 / 条件调整）变更即 bump **口径版本号**（现有 `prompt_version` 是其前身，可扩展为流派级版本）
- 口径定义**唯一入口**，禁止多处内联常量（现状是硬编码在代码里，需外化）
- 支持按版本**回算历史**，使新旧口径结果可比
- 每次推荐结果记录其生成时的口径版本

### FR-06 画像与埋点

| 采集对象 | 最小字段 | 用途 |
| --- | --- | --- |
| 流派选择 | 用户、流派、时间、是否首次、是否跳过引导 | 个性化默认流派 |
| 流派变更 | 从哪个换到哪个、时间 | 口径迁移分析 |
| 推荐曝光 | 批次、流派、标的、曝光位次 | 采纳率 / 曝光偏差校正 |
| DIY 提交 | 提交内容、初审判定、最终归属 | 用户方法论挖掘 |
| 满意度反馈 | 满意度、原因标签、关联流派与批次 | 口径迭代依据 |

所有记录必须带 `user_id`，且可导出为画像标签。

**与大赛数据打通：【已定：打通（同 user_id）】** 画像数据与模拟炒股大赛的持仓/成交数据共用同一 `user_id`，从而可回答"偏好某种流派的人，在实战里表现如何"。

## 8. 共享规则与异常

### 8.1 单一事实源

| 事实 | 唯一来源 |
| --- | --- |
| 流派定义与口径 | 流派注册表（带版本号），唯一入口 |
| 推荐批次 | 各流派自己的源表（`ai_stock_selection_runs` 等） |
| 口径版本 | 版本号字段，禁止多处内联 |

### 8.2 异常处理

| 场景 | 处理 |
| --- | --- |
| 某流派当日无候选 | 明示空态，不得静默返回空列表；提示可切换其他流派 |
| DIY 提交内容为空或无法解析 | 拒绝提交并说明原因，不进入审核队列 |
| agent 初审超时或失败 | 转人工待办，不丢单 |
| 用户切换流派过于频繁 | 限频，并提示下次可切换时间 |
| 反馈重复提交 | 以最后一次为准，保留历史记录 |
| 首次引导被跳过 | 落默认「AI 帮我选」，档案标记 `skipped`，**不再二次弹出** |

## 9. 与模拟炒股大赛的关系

**大赛是消费方，本功能是提供方。** 大赛只从本功能取三样东西（见大赛 PRD 的 FR-12）：

1. 一份**可锁定的 Top10**（开局取一次，局内不变）
2. **稳定的标的标识**（可按同一标识回溯到推荐批次）
3. **推荐理由文本**（用于大赛战报里的"本笔依据"）

**大赛不做的事**：不替本功能选择流派、不做收益归因、不预设交易策略。

> ⚠️ 注意：本期起「AI帮我选」会新增**流派维度**。若大赛开局时用户所用的流派会变化，需明确**大赛锁定的是"某一次推荐批次"，而不是"某个流派"**——否则同一局内不同选手的池子会不一致。
>
> 另：按 #13，画像与大赛数据**打通（同 `user_id`）**，可做"流派偏好 × 实盘表现"的交叉分析。

## 10. 风险与缺口

| # | 风险 | 说明 | 处置 |
| --- | --- | --- | --- |
| 1 | **后台审核系统不存在** | 现状无任何选股相关审核/配置后台，同仓库也无后台前端。DIY 的"人工复核"要从零建 | **【已定】本期只做最小形态**：待审列表 + 通过/驳回 + 归类 |
| 2 | **四个流派异构** | 数据源、生成时点、字段都不同，硬要统一展示会失真 | 走"薄封装"，允许各流派保留自己的展示形态 |
| 3 | **DIY 的可用性天花板低** | 若只能映射到已有信号维度，用户会觉得"我提的没被真正实现" | 初审输出要**如实告知**"你的方法被映射成了什么"，管理预期 |
| 4 | **样本量** | 反馈与采纳率在早期用户量小，结论不显著 | 反馈先作为定性线索，不做自动调权（本期不做） |
| 5 | 口径频繁变更导致历史不可比 | DIY 上架会不断新增流派 | 强制版本号 + 回算（FR-05） |
| 6 | 首次引导被当成"又一个弹窗" | 首次进入本就信息密集，引导可能被直接关掉 | 可跳过且不再二次弹出；引导文案只讲"有几种选法"，不讲规则细节 |
