# 智慧大脑 V4 产品北极星：像资深分析师一样思考

> 本文件记录用户对产品的最终目标，是所有架构与代码取舍的最高判据。
> 当现有架构与目标冲突时，改架构；不得用「现有架构不允许」否定目标行为。

## 1. 用户原话（2026-11-27）

> 我做这个大脑就是为了使得这个系统像一个资深分析师。如果是一个资深分析师，他确实会提前收集好新闻，但如果在分析过程中，发现还有需要找的资料，或者需要确认的信息，会根据自己的需要去网上搜索相应的关键词，拿到问题的答案，从而继续分析或矫正思路。

## 2. 目标思考方式（必须实现的行为）

1. **预读**：开工前收集行情、公告、日历、新闻底稿。
2. **立假设**：基于底稿形成可证伪的竞争假设。
3. **追问**：分析过程中发现缺口 → 主动搜索关键词 → 拿到答案。
4. **修正**：用新证据确认 / 推翻 / 调整假设，而不是硬套原结论。
5. **留痕**：每次追问的 query、结果、时间都可审计、可回放。

关键：检索不是「开题一次」，而是贯穿分析的可迭代动作。

## 3. 工程判据（架构必须满足）

- 分析阶段必须能按需检索，不是只读预置材料。
- 检索结果必须能进入证据账本并被研判引用（append-only）。
- 时间边界：`published_at > as_of` 的结果不得入账。
- 可回放：归档 query + 结果，回放时复用同一份语料。
- 有预算：每 run / 每席位检索配额、条数上限、去重、截断。
- 架构服务于行为：若「冻结证据 / 分析师无工具」阻碍追问，就必须改。

## 4. AI 工作纪律（防止「凭架构猜」）

1. 改任何代码前，先写清「要达成的分析师行为」，并用真实证据核实当前行为
   （探针 / 测试 / 日志 / 真实 run）。
2. 不许把「架构上应该是这样」当作事实；无法验证的判断必须标注「未核实」。
3. 发现实现与目标冲突时，以目标为准改造；不许把目标降级成现有架构能做到的样子。
4. 每次修改记录：目标行为 → 现状证据 → 改动 → 验证输出。
5. 用户补充新的目标效果时，追加到本文件，并在实现前复述确认。

## 5. 当前差距与方向（2026-11-27）

- 市场溯源没有新闻证据：工具层无新闻检索、profile 未配新闻组、快照只含行情 + 日历。
- 简报链冻结证据且分析师无工具（适合简报，但不应推广到深度归因）。
- 旧链可借鉴：事件库 / 财联社电报预取 + Tavily 关键词检索 + 时间过滤后冻结。
