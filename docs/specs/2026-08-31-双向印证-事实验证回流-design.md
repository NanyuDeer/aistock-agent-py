## 1. 背景与目标

### 1.1 背景

验证环现状（Spec B 已落地）：**到期价格命中为主渠道**——`prediction_validator.run_once()` 确定性判定按 `due_dates` 比对 kline 的 hit/miss，`read_validation_profile` 缓存优先读取命中率画像，`enrich_prediction_input` 反哺预判。这条渠道确定、可自动、无人值守。

但它**只回答一个问题**："预判的方向/阈值，到期价格兑现了吗？"。它不回答预判的另一个本质问题：**"预判的场景逻辑，是否被后续实际发生的事实所印证？"**

例如早报预判了"后市靠降息预期兑现驱动上行"（`conditions[]` 里含"降息预期"场景）。到期时价格可能没达到 +5%（价格 hit 判 miss），但之后**溯源归因**发现某板块上涨的根因恰恰是"降息预期兑现"。此时：

- 价格渠道：miss（涨不到，预判"错"）

- 事实验证：**场景被现实印证了**（"降息预期"这个逻辑成立，预判"逻辑对但节奏/幅度错"）

两条信号**正交**，信息量互补。只靠价格渠道，会把"逻辑正确但价格没够"的预判一刀切判错，丢失可复用的场景洞见。

同事观点确认（本次设计输入）：**"迭代不一定是逻辑层；只要系统能自我生长都算迭代"**，而\*\*"双向印证是验证"\*\*——溯源发现的事实确认历史预判的场景，这条证据本身就是一条验证信号，应回流进验证画像。

### 1.2 问题本质与缺口

| 缺口        | 现状                                   | 本 Spec 目标                                                     |
| --------- | ------------------------------------ | ------------------------------------------------------------- |
| 验证信号单一    | 只有到期价格 hit/miss（渠道A）                 | 补\*\*事实验证（双向印证）\*\*对等渠道（渠道B），分渠道记录、合并统计                       |
| 溯源与预判互不印证 | review/stock\_trace 归因时**不核对历史预判场景** | 溯源链产出归因结论后，**顺手探针**：结论的场景语义是否命中某历史预判的 `conditions[].scenario` |
| 画像信息量不足   | 画像只有命中率/条件成立率                        | 画像新增 `evidence_confirmed` 维度 + "被印证场景 / 从未被印证场景"信号            |
| 预判反哺缺场景信号 | 预判只读命中率                              | 预判产出时读到"哪些场景被现实多次印证 / 多次预判却从未被印证"，据此调权重                       |

### 1.3 关键决策（已确认 ✅）

| 决策点   | 结论                                                                         |
| ----- | -------------------------------------------------------------------------- |
| 采集点   | **挂溯源链，回流画像**（不把验证塞进溯源环本身，不改溯源职责为"验证"；溯源只在归因时采集印证证据回流）                     |
| 验证主渠道 | **保留到期价为主渠道不动**（确定性、自动、无人值守）；双向印证作为**对等渠道**，不替换主渠道                         |
| 匹配方式  | 场景**逻辑/语义层**印证（`scenario` 语义匹配），与"涨跌方向对错"正交，不与价格命中重复计                      |
| 三粒度对齐 | 采集点随溯源链天然对齐（review/sector\_trace/stock\_trace 共用 `CausalChain`），不另建第四套验证路径 |
| 迭代定位  | 印证证据是**验证画像输入**（喂给 Spec C 逻辑层迭代 + 预判反哺），**不新增迭代链路**                        |

## 2. 设计决策落地

### 2.1 溯源链挂采集点（不改 6 阶段）

统一 6 阶段因果链（`trace/chain.py` 的 `TRACE_CHAIN_STAGES`）是归因结构的唯一事实源，**不新增 stage**。改为在 `CausalChain` 追加一个可空字段：

```python
class CausalChain(BaseModel):
    nodes: list[CausalNode]
    # Spec Cbis：溯源归因时顺手核对历史预判，确认的印证证据回流验证画像（可空，非每次都有）
    confirmed_prediction: list[PredictionConfirmation] = []
```

**填入时机**：溯源在产出归因结论（`observable_result` / 结论总结）后，对该结论做一次**场景探针**：

1. 拉该 target 近期 pending/verified 预判（复用 `list_verified_predictions` / target 维度过滤）。
2. 对每条预判的 `conditions[].scenario`，判断归因结论的场景语义是否命中。
3. 命中→ 追加一条 `PredictionConfirmation`；不命中→ 不填。

> 防误判红线：必须是**场景逻辑层印证**（结论与预判场景同源），不含"涨跌方向对不对"的判定；方向对错仍由渠道A（到期价）负责。两渠道正交、不重复计。

### 2.2 回流数据结构

```python
class PredictionConfirmation(BaseModel):
    prediction_id: str            # 被印证的预判
    scenario: str                 # 命中哪个 conditions[].scenario
    source_trace_id: str          # 哪条溯源产生的确认（可追溯证据）
    confirmed_kind: Literal["scene_match", "evidence_match"]  # 场景印证 / 证据印证
    confirmed_at: datetime
```

- `scene_match`：归因结论与预判场景语义同源（默认主形态）。

- `evidence_match`：溯源引用了与预判场景同源的具体证据（`evidence_ids`），证据层面印证（更强、少用），为未来退化预留。

- `confirmed_prediction` 落在溯源产物（`MarketTraceResult`/`SectorTraceResult`/`StockTraceResult`）内，随溯源链序列化落库。

### 2.3 画像升级（`build_validation_profile` / `read_validation_profile`）

在现有 `hit_rate / condition_met_rate / miss_patterns` 之上，新增**第二渠道信号**，分渠道记录、合并统计：

```python
# 画像输出新增字段
evidence_confirmed: list[PredictionConfirmation]      # 被溯源印证的预判/场景记录（带证据链路）
scenario_harvest: {
    "confirmed": {scenario: count},    # 哪些场景被现实多次印证
    "unconfirmed": {scenario: count},  # 哪些场景多次预判却从未被溯源印证
}
```

- **读画像**时同时读两个信号，供预判反哺（§2.4）。

- **合并统计**：综合画像 = 渠道A（价格命中率）+ 渠道B（印证确认数）各自保留 + 一个综合视图；**不把两者相加成单一数字**（语义不同），对外以"两渠道分列 + 场景信号"呈现。

### 2.4 预判端消费（闭环）

`enrich_prediction_input`（Spec B 已实现）追加读 `scenario_harvest`：

| 信号            | 预判动作                             |
| ------------- | -------------------------------- |
| 某场景被多次印证      | 提高该场景在 `conditions[]` 的默认权重 / 置信 |
| 某场景多次预判却从未被印证 | 降权 / 标记"高不确定"，提示 LLM 谨慎          |

> 展示侧：如可复用 `morning_forecast` 的摘要位，追加一行"近 N 期被现实印证的场景"，但**不落库**（对齐 Spec B §2.2 边界声明），仅展示侧反哺。

## 3. 三粒度对齐

| 环节             | 大盘                           | 板块                  | 个股                     | 本 Spec 动作                            |
| -------------- | ---------------------------- | ------------------- | ---------------------- | ------------------------------------ |
| 价格验证（渠道A）      | ✓ index                      | ✓ sector            | ✓ stock（Spec B 已接个股 K） | 不动                                   |
| 事实验证（渠道B·溯源回流） | review 归因时采集                 | sector\_trace 归因时采集 | stock\_trace 归因时采集     | **采集点挂共用** **`CausalChain`，三粒度自动对齐** |
| 画像读取           | read\_validation\_profile 统一 | 同左                  | 同左                     | 画像字段升级，统一接口不变                        |
| 预判反哺           | enrich\_prediction\_input 统一 | 同左                  | 同左                     | 读新增场景信号                              |

> 结论：**印证采集点随溯源链天然对齐，不额外建第四套验证路径**。到期价主渠道三粒度已通，本 Spec 只在其上加"溯源回流"这一条渠道。

## 4. 边界

| 边界               | 说明                                                                        |
| ---------------- | ------------------------------------------------------------------------- |
| **不改溯源环职责**      | 溯源仍是归因，不变成"验证环"；只在归因后**顺手采集印证证据**回流。不满足"溯源本身要有验证预判逻辑"（会导致溯源职责变重、到期验证变慢变贵） |
| **不新增迭代链路**      | 印证证据只作为验证画像输入 + 预判反哺信号，喂给 Spec C 已有的"逻辑层迭代"；不新增"印证层迭代"独立闭环                |
| **不建独立印证 agent** | 不设独立 agent/独立环，采集点内联溯源链                                                   |
| **渠道不合并单数**      | 到期价命中 vs 事实验证语义不同，分渠道记录，不sum成单一数字（防语义混淆）                                  |
| **场景匹配不做方向判定**   | confirmed\_kind 只记"场景/证据印证"，不含涨跌方向对错（方向归渠道A）                              |
| 与 Spec C 边界      | 不改变逻辑层变体/回放/晋升流程；仅增加画像输入维度 + 溯源采集点                                        |

## 5. 实施要点（aistock-agent-py）

### 5.1 溯源链 + 回流（核心）

- `schemas/market_trace.py`：`CausalChain` 追加 `confirmed_prediction: list[PredictionConfirmation]`（默认空）；新增 `PredictionConfirmation` schema。

- 新增溯源采集函数（如 `skills/scene_probe.py` 或 `services/`）：输入归因结论 + target → 拉近期预判 → 场景语义匹配 → 产出 `PredictionConfirmation` 列表。

- 三处溯源产物构造点（review / sector\_trace / stock\_trace）在生成 `CausalChain` 时调用采集函数，回填 `confirmed_prediction`（可空，失败降级不阻断归因）。

### 5.2 画像升级

- `prediction_stats.py` `build_validation_profile`：消费预判链路新增字段（画像落库端，若画像源含 confirmed 数据）；aggregate 出 `evidence_confirmed` + `scenario_harvest`。

- `skills/prediction_validation.py` `read_validation_profile`：返回结构加渠道B信号。

### 5.3 预判反哺

- `skills/prediction_validation.py` `enrich_prediction_input`：追加读 `scenario_harvest`，按 §2.4 表调整 `conditions[]` 权重/标注。

- （展示侧，可选）`morning_forecast_extractor` summary 追加"被现实印证的场景"一行，不落库。

## 7. 非目标

- 不把"验证"并入溯源环职责。

- 不新增独立"印证层"迭代闭环（印证只作画像输入，逻辑层迭代不变）。

- 不重建第四套验证路径。

- 不做"未来第五粒度"的预留（YAGNI）。
