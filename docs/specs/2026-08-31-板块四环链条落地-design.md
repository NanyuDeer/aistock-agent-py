> 日期：2026-08-31
> 状态：**待实施**（板块粒度四环全落地；级联预判决策需用户确认，见 §3）
> 关联 Spec：`2026-08-31-四环三粒度复用架构-design.md`（全局指导，本文档的约束来源）、`2026-08-28-sector-trace-design.md`（板块溯源设计稿，已过时需回改）、`2026-08-31-条件化预判改造-design.md`（Spec A，板块预判复用 conditions[]）、`2026-08-31-预判验证-design.md`（Spec B，板块验证消费画像）、`2026-08-31-预判迭代改进-design.md`（Spec C，板块迭代复用验证评分器）
> 涉及仓库：aistock-agent-py（核心）、aistock-app-api（报告白名单/落库）

## 1. 背景与目标

### 1.1 背景

板块是四环三粒度中**唯一四环断裂**的粒度：

| 环 | 现状 |
|---|---|
| 溯源 | ◷ `sector_trace` 设计稿（`2026-08-28-sector-trace-design.md`），**仅设计未动工，且已过时**（未对齐 Target 维度） |
| 预判 | ✗ **无板块预判入口** |
| 验证 | ✓ `classify_target` 已支持 sector（`resolve_sector_target` → 板块日 K `get_ths_daily_range`） |
| 迭代 | ◷ 设计稿规划注册 `sector_trace` adapter，未落地 |

板块是"四环三粒度架构"的**完整体现**：它要求溯源、预判、验证、迭代四环串成闭环，且**唯一涉及跨粒度级联**（大盘溯源结论 → 板块预判输入）。板块落地后，三粒度矩阵才真正打穿。

### 1.2 目标

1. **板块溯源落地**：按过时设计稿落地 `sector_trace`（事件层归因），并**回改对齐 Target 维度**。
2. **板块预判新增**：`predict(target=Target(kind="sector"), sector_snapshot)`，复用 `PredictionResult + conditions[]`。
3. **板块验证打通**：板块预判 target 走 sector 验证（已有数据源，接入验证 skill）。
4. **板块迭代挂载**：注册 `sector_trace` adapter + 板块预判验证评分器。
5. **级联预判**（关键决策）：大盘溯源结论作为板块预判输入（见 §3）。

## 2. 现状梳理

### 2.1 过时设计稿（sector_trace）回顾

`2026-08-28-sector-trace-design.md` 已规划的内容（**大部分仍有效，需回改对齐 Target**）：

| 环节 | 设计稿内容 | 是否需要回改 |
|---|---|---|
| 溯源层级 | 大盘（板块层）→ 板块（事件层）两层 | 不改 |
| 触发 | `review_done` 事件链 + `SectorTraceConsumer`（`sector_chain` 消费组） | 不改 |
| 归因对象 | 仅主因板块（primary 链命中板块，回退 top_losers[0]） | 不改 |
| 归因结构 | 事件级主因链（现象确认 → 事件 trigger → transmission → impact），复用 `ChainStage` | 不改 |
| 板块快照 | 板块行情 + 定向事件检索（3 类 query：暴跌原因/事件公告/监管调查） | 不改 |
| 持久化 | `report_type="sector_trace"`，Node 白名单加类型 | 不改 |
| 迭代 | 注册 `sector_trace` adapter + `sector_close_snapshot` 产片源 | **需补板块预判验证评分器** |

**需回改的点**（过时设计稿缺失，全局架构新增）：
- 未对齐 `Target(kind="sector")` 维度（设计稿用板块名字符串）。
- **未规划板块预判**（设计稿只到溯源 + 迭代，预判完全缺失）。
- 未规划板块验证的 skill 接入（验证数据源已有，但无画像消费）。
- 未决策级联预判（大盘溯源 → 板块预判）。

## 3. 设计决策（已确认 / 待确认）

| 决策点 | 结论 |
|---|---|
| 溯源层级 | 大盘归因到板块层（终点）；板块溯源归因到**事件层**（不套大盘 4 类，用事件级主因链） |
| 触发方式 | `review_done` 事件链 + `SectorTraceConsumer`（复用现有事件链模式，非新触发方式） |
| 归因对象 | 仅主因板块（primary 链命中板块，回退 top_losers[0]，无则跳过） |
| **板块预判入口** | 新增 `predict(target=sector, sector_snapshot)`，复用 `PredictionResult + conditions[]`，走统一入口的 **fast path**（板块快照是结构化输入） |
| **级联预判（✅ 已确认）** | 大盘溯源结论作为板块预判输入，采用**输入组装**——板块预判运行时主动拉当日大盘溯源结论（`get_analysis_report("review")` 的 `market_trace.trace`）作上下文，**不做事件驱动**（遵守全局 §9"不做新触发方式"） |
| 板块验证 | 复用 Spec B 验证 skill；target 走 `classify_target` → sector → `get_ths_daily_range`；画像 key 用 `Target.internal_id` |
| 板块迭代 | 注册 `sector_trace` adapter（溯源历史切片）+ 板块预判验证评分器（预判验证驱动），**双链路分离**（全局 §3.4） |
| 领涨板块 | 不做（仅主因板块，过时设计稿已定） |

> **级联预判是 Spec D 最关键的决策**。若选择"输入组装"，板块预判能继承大盘的"大盘情绪/资金面"结论，避免板块预判与大盘预判老死不相往来。若不做，必须在非目标显式声明。

## 4. 四环改造范围（aistock-agent-py 核心）

### 4.1 板块溯源（sector_trace 落地 + 回改对齐 Target）

**基于过时设计稿，改动点**：

| 文件 | 改动 |
|---|---|
| `services/sector_trace_snapshot.py`（新增） | 板块快照构建：输入改为 `Target(kind="sector")` + `report_date`；证据采集复用设计稿 3 类定向检索 |
| `agents/workers/sector_trace.py`（新增） | 归因 worker：`run_sector_trace(*, target: Target, report_date, sector_name)` → 事件级主因链（`ChainStage`）；入口对齐 iterate `run_entry="run"` |
| `services/event_consumers.py`（改） | 新增 `SectorTraceConsumer`（`sector_chain` 消费组，消费 `review_done`） |
| `prompts/workers/sector_trace.py`（新增） | 板块事件级归因 prompt |
| `schemas/sector_trace.py`（新增） | `SectorTraceResult`（复用 `ChainStage`，同源归因链结构） |
| Node 白名单 | `VALID_REPORT_TYPES` 加 `'sector_trace'` |

**关键回改**：过时设计稿用"板块名字符串"定位主因板块，改为 `Target(kind="sector", internal_id, name)`——主因板块判定从 review 的 `market_trace.trace` 提取板块名后，经 `resolve_sector_target` 得到稳定 `internal_id`，画像 key 用它。

### 4.2 板块预判（新增，复用 conditions[]）

- **入口**：`predict(target=Target(kind="sector"), sector_snapshot)`，收敛到 Spec A 统一入口的 **fast path**（板块快照是结构化输入，条件分支模板套用）。
- **级联输入**（若采纳）：板块预判输入构造时，`enrich` 当日大盘溯源结论（`market_trace.trace` 的 primary_chain 摘要）作为"大盘环境"上下文。
- **输出**：`PredictionResult + conditions[]`（Spec A 已定义，含 `anchor.direction`）。
- **落库**：`forecast_snapshot`（全局 §4.2），`target_kind="sector"`。

### 4.3 板块验证（复用 Spec B skill）

- 板块预判的 target 经 `classify_target` → `sector` → `resolve_sector_target` → 板块日 K（`get_ths_daily_range`）。
- 复用 Spec B 的 `_verify_conditions`（condition_met 复用 `ma_breadth`，板块阈值用 `SECTOR_THRESHOLDS`：neutral 0.25% / strong 3.0%）。
- 画像 key 用 `Target.internal_id`。

### 4.4 板块迭代（双链路）

- **链路一（溯源迭代）**：注册 `sector_trace` adapter（过时设计稿已规划）：`ground_truth_kind="attribution"`、`case_sources=(sector_close_snapshot,)`、`data_deps` 复用 market/search。
- **链路二（预判迭代）**：板块预判接入 Spec C 的验证驱动闭环，`evaluate_verification` 评分器（按 sector 粒度分层阈值）。

## 5. 数据流

```
review(ok) → publish_review_done
                │
                ├─ PredictionConsumer（现有，大盘预判）
                └─ SectorTraceConsumer（新增）
                     ├─ 1. 查 review 报告，提取主因板块 → Target(kind=sector)
                     ├─ 2. build_sector_snapshot（板块行情 + 定向检索）
                     ├─ 3. run_sector_trace → SectorTraceResult（事件级主因链）
                     ├─ 4. save_analysis_report("sector_trace")
                     └─ 5. predict(target=sector, sector_snapshot)  ← 板块预判（级联输入大盘结论）
                          └─ conditions[] 落 forecast_snapshot（due_dates 锚点）
                               └─ 16:00 run_once 验证 → 画像（internal_id key）
                                    └─ 17:00 迭代（双链路：sector_trace 切片 + 板块预判验证）
```

## 7. 测试要点

- 主因板块判定：primary 链命中板块 / 回退 top_losers[0] / 无板块跳过。
- `SectorTraceConsumer`：review_done → 消费 → run_sector_trace → 落库。
- 板块预判：`predict(target=sector)` 输出 `conditions[]`；级联输入（大盘结论）正确并入。
- 板块验证：target 经 classify_target → sector → 板块日 K；画像 key 用 internal_id。
- 板块迭代：sector_trace adapter 注册；板块预判验证评分器（sector 分层阈值）。
- **存储狙击实测**：7-16 切片走 `sector_close_snapshot` 产片 → GT → `run_case.py sector_trace`，验证板块溯源归因到"韩国检方突袭存储三巨头"事件层。

## 8. 风险与注意事项

- **级联预判依赖 review 报告**：板块预判拉当日大盘结论时，若 review 未完成/失败，级联降级为"无大盘环境"（不阻断板块预判）。
- **板块名解析脆弱性**：`resolve_sector_target` 按名解析，改名断画像——Target 用 `internal_id` 兜底（全局 §2.1）。
- **定向检索限制**：板块溯源能否归因到具体事件受搜索返回内容限制（过时设计稿 §7 已预期）。
- **双链路分离**：板块溯源走归因切片迭代，板块预判走验证驱动迭代，勿混用评分器（全局 §3.4）。
