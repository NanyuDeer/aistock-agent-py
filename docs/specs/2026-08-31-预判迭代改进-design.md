## 1. 背景与目标

### 1.1 背景：迭代闭环的现状

项目已有**两层面迭代**：

| 层面                                    | 现状                                                                                                                                    | 覆盖对象                           |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------ |
| **层面一：历史切片监督式迭代**（`iterate/` 子包）      | 16:30 产片（case\_builder）→ 17:00 消费（variant\_engine 生成变体 → replay 回放 → evaluator 归因评分 → reporter 报告）；`ITERABLE_AGENTS` 注册表驱动，不硬编码 agent | review、event\_analyst（**归因类**） |
| **层面二：每日实时迭代**（`iterate_analyzer.py`） | 四维阈值评分卡（hit\_rate / mean\_deviation / attribution\_match\_rate / sentiment\_bias）+ LLM 偏差分析；**只读+建议，不自动改**                            | 通用（含溯源/预判质量）                   |

**关键缺口**：预判（prediction）**未接入任何迭代闭环**——`ITERABLE_AGENTS` 只有 review/event\_analyst，且它们的迭代是"标准答案对照"（归因类），而预判的"标准答案"是**到期验证结果**（hit/miss/condition\_met）。预判目前改逻辑靠人工（如老师 8/28 会议提"预判要加条件"后手工重写 prompt），无自动闭环。

### 1.2 用户确认的闭环逻辑（✅ 已确认）

> **溯源-预判-验证-迭代 四环链路**：
>
> - **溯源（review/event\_analyst）**：只能走**历史切片监督式迭代**（产出无未来锚点，靠标准答案对照）——已接入，保持。
>
> - **预判（prediction）**：必须走**验证驱动迭代**（产出有 `due_dates` 到期锚点，验证结果 = 标准答案）——本 Spec 实现。
>
> - **验证**：由 `2026-08-31-预判验证-design.md` 提供画像输入。

### 1.3 目标

1. **预判接入迭代闭环**：新增 `prediction` 的 `IterableAgentAdapter`，但迭代的"标准答案"从归因对照改为**验证画像**（`read_validation_profile`）。
2. **验证驱动变体实验**：验证画像显示某 target/condition 类型命中率低 → 生成预判逻辑变体（prompt 调整/条件生成规则调整）→ 历史到期数据回放 → 评分 → 最优变体回写预判 prompt。
3. **闭环自动化**：每日验证后（16:00 之后），若画像触发迭代阈值 → 自动排队变体实验 → 次优/最优变体落盘，人工审核后合入（对齐 iterate 现有"只读+建议，禁止自动写生产文件"红线）。
4. **大改可接受**：用户明确"不介意大改，以逻辑完善且闭环为主"。

## 2. 现状梳理

### 2.1 iterate 闭环组件（已有，复用）

| 组件                  | 职责                                                                                                                           |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `adapters.py`       | `IterableAgentAdapter` 注册表（agent\_id/module\_path/prompt\_files/data\_deps/ground\_truth\_kind/case\_sources）；加 agent 只加一条记录 |
| `case_builder.py`   | 产片（按 case\_sources 从数据源切历史案例）                                                                                                |
| `variant_engine.py` | 生成/应用/恢复变体（prompt\_diff / workflow\_diff / data\_source\_diff），LLM 基于当前实现+标准答案+差距生成补丁                                        |
| `replay_layer.py`   | 回放（用切片冻结数据重跑 agent）                                                                                                          |
| `evaluator.py`      | 归因评分（方向 0.2 / 归因要素 0.5 / 板块 0.3）——**仅归因**                                                                                    |
| `reporter.py`       | 每日汇总报告                                                                                                                       |
| `scheduler.py`      | 16:30 产片 + 17:00 消费（cron，显式 Asia/Shanghai）                                                                                   |

**现状局限**：

- `ground_truth_kind` 只有 `"attribution"`（evaluator 是归因评分器），**无预判验证评分器**。

- `data_deps` 的回放键（news/market/global）面向归因，预判的"回放输入"是**历史快照 + 到期实际行情**。

- `variant_engine` 的变体是改 agent 源文件（prompt），预判变体同样改 `prompts/workers/prediction.py`。

### 2.2 验证画像（预判验证 spec 提供）

`read_validation_profile(target: Target, horizon)` → `{hit_rate, n, ci, sufficient_sample, condition_met_rate, miss_patterns, horizon_breakdown}`——本 Spec 的迭代触发输入。**`target`** **是全局** **`Target`** **对象，画像 key 用** **`internal_id`**（对齐全局 §2）。

## 3. 设计决策（已确认）

| 决策点                            | 结论                                                                                                                                                                 |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 预判迭代方式                         | **验证驱动**：标准答案 = 到期验证结果（hit/miss/condition\_met），**非归因对照**                                                                                                          |
| 接入方式                           | 复用 `ITERABLE_AGENTS` 注册表 + `variant_engine` 变体机制，新增 `prediction` adapter + **预判验证评分器**（evaluator 扩展或新 evaluator）                                                   |
| 触发时机                           | 每日 16:00 验证 + 画像更新后，`_report_stats` 之后检查画像阈值（命中率 < 阈值 or miss\_patterns 增长）→ 排队变体实验                                                                                |
| 闭环落地程度                         | **大改可接受**：验证 → 画像 → 触发 → 变体 → 回放 → 评分 → 建议回写（最优变体落盘 + 人工审核，不自动覆盖生产 prompt，对齐 iterate 只读红线）                                                                         |
| 溯源边界                           | 溯源保持历史切片监督式，**不引入验证**（无到期锚点）                                                                                                                                       |
| 变体回写                           | 落盘 `data/experiments/{case}_r{n}.json` + 建议报告；生产 prompt 变更需人工确认（对齐 iterate `禁止自动写生产文件` 红线）                                                                         |
| 与验证 spec 边界                    | 验证 spec 产画像；本 Spec 消费画像做变体实验，不重定义画像                                                                                                                                |
| 与 `iterate_analyzer` 边界（⚠️ 决策） | **两层互补，不冲突**：`iterate_analyzer` 做**每日全局四维评分卡+只读分析建议**（所有 agent 全量）；本 Spec 做**目标级验证驱动变体实验**（只针对预判命中触发阈值的 target），变体落盘建议后才需要人工决策。`iterate_analyzer` 保留，本 Spec 补充不替代。 |
| **双链路分离（✅ 对齐全局 §3.4）**         | 溯源迭代（历史切片 → 归因评分 `evaluate_attribution`）与预判迭代（到期验证 → 验证评分 `evaluate_verification`）是**两条独立链路**，评分器/触发条件/更新对象均不同，**不得混用**——预判迭代绝不改溯源 prompt，反之亦然                     |
| **变体晋升双闸门（✅ P1，对齐全局 §5.3）**    | 人工审核 + **冻结回归评测集**：从已验证样本按"粒度×场景"分层抽样冻结金标准案例，任何变体落盘前在新旧 prompt 各跑一遍、分层得分不降才准入人工审核（人审 prompt diff 审不出回归）                                                            |
| **阈值分层（✅ P1，对齐全局 §5.3）**       | 迭代触发阈值按"粒度 × horizon × 场景"分层定义，**非全局一个数**——防单层样本不足 30 导致某些场景永远不触发                                                                                                  |

## 4. 改造范围（aistock-agent-py 核心）

### 4.1 prediction IterableAgentAdapter（adapters.py 新增）

```python
"prediction": IterableAgentAdapter(
    agent_id="prediction",
    module_path="aistock_agent.services.prediction_service",
    run_entry="predict_from_trace",  # 或独立 replay 入口
    prompt_files=("src/aistock_agent/prompts/workers/prediction.py",),
    workflow_files=("src/aistock_agent/services/prediction_service.py",),
    tool_categories=("prediction",),
    data_deps={"market": "market_snapshot"},  # 回放输入：历史快照
    ground_truth_kind="verification",  # 新增：验证画像为 ground truth
    case_sources=(CaseSourceSpec("prediction_verified_scan"),),  # 新增产片源
    description="影响持续性预判：conditions[] 条件化输出，验证驱动迭代",
)
```

**新增** **`ground_truth_kind="verification"`**：variant\_engine 生成变体时，差距分析输入改为验证画像（非归因标准答案）。

> **⚠️ 回放输入三粒度（衔接 Spec D）**：`data_deps` 目前仅 `market`（大盘快照）。板块/个股预判回放需各自快照源，落地时按 `TargetProfile.snapshot_builder`（全局 §2.3）扩展 `data_deps`（`sector`/`stock` 分支），勿把三粒度快照源写死进 `prediction` adapter 一条记录。

### 4.2 预判验证评分器（evaluator 扩展，新增）

`evaluate_verification(prediction, verification_entries)` → `{score, hit_rate, condition_met_rate, miss_insights}`：

- **基础分**：到期 hit\_rate（确定性，来自验证画像）——与归因评分器并列，不混用。

- **condition 维度**：condition\_met 命中率、miss\_patterns 归类（"涨幅阈值过高" / "条件方向误判" / "volume 条件未触发"）。

- **方向维度**：direction 与到期实际方向一致性（复用归因 evaluator 的 direction 判定思路）。

- **评分输出**：变体实验对比"基线 vs 变体"的验证评分，取高者。

### 4.3 产片源：prediction\_verified\_scan（case\_sourcers 新增）

从已验证的 `prediction_records` 切历史案例：

- 输入：`verification` 非空且 schema\_version=3.0 的记录（有 due\_dates + hit/miss）。

- 每案例 = 一条预测记录：`{target, conditions[], due_dates, verification entries, 当时快照}`。

- 回放输入：历史市场快照（data\_deps market）。

### 4.4 迭代调度（scheduler 扩展）

- 复用 `_run_iterate_build_task` / `_run_iterate_daily_task` 节奏（16:30 产片 / 17:00 消费）。

- **新增触发链**：16:00 `prediction_validator.run_once` 完成后（或 17:00 消费时）检查画像：

  - 画像 `sufficient_sample` 且 `hit_rate < 该层阈值` 或 `miss_patterns` 较前日增长 → 标记该 target 待迭代；

  - 待迭代 target 进 `produce_cases_daily`（切历史验证案例）→ `_run_iterate_daily_task` 消费。

- **阈值分层配置（✅ 对齐全局 §2.3/§5.3）**：迭代触发阈值按"粒度 × horizon × 场景"分层定义，统一读 `get_iterate_threshold(target, horizon, scenario)`（全局 §2.3 统一取值函数：`TargetProfile.score_threshold` 为 `float | dict`，粒度由 kind 隐含，见全局 §2.3 注释）而非全局一个 `config.py` 常量——防单层样本不足 30 永远不触发。**P1/P5 不得读裸** **`score_threshold`** **float，必须走取值函数**，默认值回落 `_default`。

### 4.5 变体引擎适配（variant\_engine 扩展）

- **不新增 VariantType**：现状 `VariantType = Literal["prompt_diff", "workflow_diff", "data_source_diff"]`。预判的"conditions 生成规则调整"本质是改 prompt（阈值/条件类型/方向提示），**复用** **`prompt_diff`** **类型**，走现有 generate\_variant / apply\_variant / restore\_baseline 管线（git checkout 幂等）。

- 差距分析输入：验证画像（hit\_rate/miss\_patterns）+ 当前 `PREDICTION_PROMPT` + 历史回放结果。

- LLM 生成变体：调整 prompt 中的 conditions 生成指令（如"short 档条件常因 threshold 过高 miss，改为更窄 threshold"）。

- 回放 + 评分：用历史验证案例重跑 `predict_from_trace`（或轻量入口），`evaluate_verification` 对比基线/变体。

### 4.6 报告与回写（reporter 扩展）

- 每日报告新增"预判迭代"区块：画像趋势（hit\_rate 走势）、触发维度、变体对比（基线 vs 变体评分）、建议。

- **回写红线**：最优变体**落盘建议**（`data/experiments/`），**不自动覆盖生产 prompt**——人工审核后合入（对齐 iterate\_analyzer"只读+建议"红线，用户确认大改但生产文件仍需人工闸门）。

### 4.7 冻结回归评测集（新增，变体晋升闸门）

- **产金标准案例**：从已验证样本按"粒度（index/sector/stock）× 场景（上行/下行/震荡）"分层抽样，冻结一批案例（每层 N 条，冻结后不再变动）。

- **变体晋升前回归**：任何变体落盘建议前，在新旧 prompt 上各跑一遍金标准案例，`evaluate_verification` 分层评分；**新版本分层得分不低于旧版本才允许进入人工审核**（与人工审核并列双闸门）。

- **存储**：金标准案例清单存 `data/regression_golden/`，随样本积累可增量冻结（但已冻结案例不替换）。

## 5. 数据流

```
16:00 验证（run_once + 画像落库）
        │
        ▼
16:30 产片：检查画像阈值 → 触发 target 切历史验证案例（prediction_verified_scan）
        │
        ▼
17:00 消费：variant_engine 生成预判变体（差距分析=验证画像）
        │
        ▼
   replay（历史快照回放 predict_from_trace）→ evaluate_verification（基线 vs 变体）
        │
        ▼
   reporter 每日报告（画像趋势 + 变体对比 + 建议）→ 最优变体落盘待人工审核
```

## 7. 测试要点

- `evaluate_verification`：命中率/condition\_met 分布/miss\_patterns 归类；空画像降级。

- adapter 注册：`ITERABLE_AGENTS["prediction"]` 存在且 ground\_truth\_kind 生效。

- 产片源：只切 schema\_version=3.0 且 verification 非空记录；无记录不产片。

- 变体引擎：`prompt_diff` 复用（生成/应用/恢复 restore\_baseline 幂等）；变体不破坏 prediction\_service 其余路径。

- 触发链：画像命中率 < 该层阈值才触发；`sufficient_sample` 为 false 不触发（样本不足防误触发）。

- 阈值分层：按"粒度×horizon×场景"分层取 `TargetProfile.score_threshold`，断言单层样本不足时不触发、跨层不误触发。

- 回归评测集：金标准案例分层抽样冻结；变体晋升前新旧 prompt 对比，新版本分层得分不降才准入。

- 回写红线：变体只落盘建议，**不修改生产 prompt 文件**（断言源文件未变）。

- 与归因 evaluator 隔离：预判评分不混入归因评分桶（防桶污染，对齐 prediction\_stats 经验）。

## 8. 风险与注意事项

- **回放成本**：`predict_from_trace` 回放需历史快照 + LLM 调用（deep\_think），变体实验次数需受限（`iterate_max_daily_cases` 复用 + 每 case 最大轮次），防 token 爆炸。

- **LLM 变体质量**：变体是 LLM 生成的 prompt 补丁，`restore_baseline` 必须可逆（git checkout 幂等，对齐现有 variant\_engine）；diff 校验失败丢弃。

- **阈值误触发**：`sufficient_sample` 必须 n>=30 才触发（对齐 stats 的 sufficient\_sample 语义），防小样本抖动触发迭代。

- **与验证 spec 边界**：本 Spec 消费画像不改画像；画像字段变更需两 spec 同步。

- **生产文件红线**：最优变体落盘建议 + 人工审核，不自动覆盖 `prompts/workers/prediction.py`——即使"大改可接受"，生产 prompt 变更仍需人工闸门（对齐 iterate 现状）。
