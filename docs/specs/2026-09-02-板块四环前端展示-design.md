# 板块四环前端展示 — Design Spec v0.2（已定稿）

> 状态：**已定稿并全链路实施（2026-09-02）**（D4/D6 已确认；组件库 InsightCard 升级按用户多轮评审定稿）
> 日期：2026-09-02
> 范围：aistock-app-frontend（uni-app）+ aistock-app-api（Node 聚合接口）+ aistock-agent-py（长线风口批量预判生产支撑）
> 关联：`2026-08-31-四环三粒度复用架构-design.md`（总架构）、`2026-09-02-sector-four-loop-specc.md`（板块四环 Spec D）

## 1. 背景与目标

板块四环在 agent 后端已闭环（Spec D），App 前端无页面消费"板块溯源 + 板块预判"。本 spec 定义展示形态、入口、配套后端查询接口，并补上**长线风口板块的预判生产触发**（用户语义修正：长线风口是"预判逻辑"而非"溯源逻辑"）。

**核心语义（用户修正，架构依据）**：
- **环按来源分化**，板块本身不强制四环全有：
  - 大盘溯源主因板块（review_primary）→ **溯源 + 预判 + 验证**
  - 长线风口板块（wind_leader）→ **预判 + 验证**（它是被持续预判/跟踪的候选池，不是当日异动溯源对象）
  - 迭代为后端机制，**前端不展示任何迭代相关内容**（D5 已定）
- 前端展示的洞见语义 = 板块溯源（当日为什么）+ 板块预判（接下来怎么走）→ 用**洞见组件卡片**（InsightCard 系）承载，而不是包在非洞见的行情/流向图上。

## 2. 需求（v0.3 信息架构修正：洞见卡组件复用 + B 页白卡 + 按来源分流跳转）

**结构修正（2026-09-02 用户确认）**：不再"统一跳板块详情"，改为——

- **核心组件 · 板块洞见卡**（洞见样式：溯源+预判+验证）：由组件库 `InsightCard` 升级而来（预判部分适配条件化，§7.2）。**复用到两个来源页**：
  1. 风口详情页 `sector-detail.vue`（风口板块语境）；
  2. 大盘溯源页 `analytics/traceability.vue`（大盘主因板块语境）。
- **页面 B · 板块四环日报**（新建，`modules/market`）：**不用洞见卡样式**，简单**白卡列表**聚合"当日哪些板块被溯源/预判、来源、方向、验证状态"，日期回看近 7 天（D2）。
- **跳转分流（点 B 页白卡行）**：来源=风口板块 → 风口详情页 sector-detail（内嵌该板块洞见卡）；来源=大盘主因板块 → 大盘溯源页 traceability（主因板块区嵌洞见卡）。**主因板块不再被导向风口详情页** → 原"主因板块无行情/K线"缺口消解（§11）。
- **入口**：① 长线风口 `leaders.vue` 顶部 → B 页；② 大盘溯源页 traceability 板块洞见卡旁 → B 页（可选）。
- **sector-detail 回退**：AI 分析卡从洞见化样式（commit 3c319a2）回退为未洞见化原样式（保留层级流向图）；洞见卡作为**独立新增卡**。

## 3. 板块分类现状（调研结论）

三套并存标识（详见 v0.1 §3，结论不变）：

| 体系 | 形态 | 分类 | 位置 |
|---|---|---|---|
| 同花顺 ts_code | `881xxx.TI`(行业) / `885/886xxx.TI`(概念) | ths_index I/N | 复盘快照板块行情（带 ts_code）；板块 Target 画像 key |
| 同花顺裸 code | `881/885/886xxx` | 前缀区分行业/概念 | 长线风口 `hot_sectors[].code`、板块 K 线 |
| BKxxxx tag | `BK0475` | 概念 tag | tag 龙头（本 spec 排除） |

**不可靠**：`hot_sectors[].type`（行业也标 concept）——分类判定用 code 前缀或 ths_index type，不用 type。
**前端现状**：板块身份以 name 为主键；`MarketTraceSectorItem` 无 code；大盘溯源页落点=`analytics/traceability.vue`；`sector_trace` 已有公开通道 `/api/agent/report/sector_trace/:date`（TTL 7 天）；`sector_prediction` 混在 `/api/predictions`（无 source_type 过滤）。

## 4. 每日板块候选集与环分化（用户约束）

```
候选 = 长线风口当日 hot_sectors ∪ 大盘溯源主因板块（按 ts_code 去重）
环分化：
  wind_leader 板块   → 预判 + 验证（无溯源）
  review_primary 板块 → 溯源 + 预判 + 验证
（同一板块两来源都有 → both，按 review_primary 处理，含溯源）
```

**缺口（生产侧）**：长线风口板块目前无批量预判生产方（只有对话 `predict_sector_trend` 随机触发 + 溯源级联）。要让页面 B 的风口板块有"预判-验证"数据，需 agent 每日对风口板块批量 `predict_sector`（见 §6.4）。数量与节流见 D6。

## 5. 多来源统一数据获取逻辑

板块稳定标识 = 同花顺 ts_code（`*.TI`，对齐 agent 侧 Target.internal_id/画像 key 体系）。归一管线（后端聚合服务）：
1. 两来源取行：`wind_leaders.hot_sectors`（name+裸 code+cycle）∪ review `snapshot.a_share.sectors` 四桶（name+ts_code(.TI)+行情）。
2. 归一到 ts_code：已有 `.TI` 直接用；裸 6 位 code 补 `.TI`；仅 name → `/internal/ths/resolve`（剥后缀三级匹配）→ ts_code；失败剔除并标注。
3. 分类：`881`→industry，`885/886`→concept（不用 type）；来源标注 `source ∈ {wind_leader, review_primary, both}`。
4. 展示名以 ths resolve name 为准（去「板块」等后缀），防异名重复（"存储" vs "存储板块"同 ts_code 合并）。

## 6. 后端设计

### 6.1 现状
- `sector_trace`：公开 `GET /api/agent/report/sector_trace/:date`（无报告回退最近一份），TTL 7 天。
- `sector_prediction`：`prediction_records`（source_type=`sector_prediction`，source_id=`sector:{板块中文名}:{date}`），`/api/predictions` 无 source_type 过滤，记录常驻。

### 6.2 Agent 反代聚合接口（D1 已定：推荐方案）
新增 `GET /api/agent/sector-insight/:date`（app-api 聚合，前端零拼装）：
```
{
  date, hasData: bool,
  candidates: [                    // §5 归一后的当日候选（含两来源并集）
    { ts_code, name, category: industry|concept, source: wind_leader|review_primary|both,
      cycle?: long|short,
      quote: { pct_change, net_amount, lead_stock, company_num } | null,
      trace: { present: bool, status: completed|insufficient, summary, evidence_count } | null,   // 仅 review_primary/both；wind_leader 恒 null
      prediction: { present: bool, status: pending|verified, due_date, direction, confidence, horizons:[…] } | null,
      verification: { result: hit|miss|null, actual, verified_at } | null } ]
}
```
实现：app-api 读 hot-sectors.json / review 报告 / sector_trace 报告 / prediction_records 聚合。**不含迭代画像信息**（前端不展示迭代，D5）。

### 6.3 生产支撑（agent-py，页面 B 数据成立的前提）
新增**每日长线风口板块批量预判**任务（scheduler/定时）：
- 标的（D6 已定 = **leaders 页前端可见集合**）：与 `leaders.vue` 同口径——`hot_sectors` 过滤后（长线按 `long_term_days`、短线按 `freq20` 排序各取 **top 8**）的**两档并集**（去重）；
- 动作：逐板块 `predict_sector(report_date, sector_name, sector_snapshot={})`（复用 Spec D 入口，prompt 内联同板块级联口径；板块快照可在后续增强）；
- 幂等：source_id=`sector:{name}:{date}` UNIQUE，Node upsert 已保证；已存在记录跳过（防重复触发/重复扣 LLM）；
- 产出 → pending → 16:00 到期验证 → 画像/迭代（与溯源级联的预判同链路，不新增评分逻辑）。
- 溯源环不为其触发（长线风口不溯源，仅预判）。

### 6.4 备选（不推荐）
`/api/predictions` 加 source_type 过滤 + 前端三路拼装（丢归一、异名难处理、前端重）。

## 7. 页面与组件设计（v0.3）

### 7.1 sector-detail AI 分析卡回退（前置）
还原 commit 3c319a2 引入的洞见化包装（InsightTag「板块洞见」标签头 + 蓝卡配色/渐变分隔线样式），恢复洞见化前样式；层级流向图功能保留（含 renderjs）。只动样式/头部，不动数据逻辑与其它提交修复。

### 7.2 组件库 InsightCard 升级（预判部分适配条件化）★ 最先做，画图确认后实施
- 现状：InsightCard `forecast` 为一句文本（≤2 句上限），无法表达已条件化的预判（PredictionResult.conditions[] + horizons 方向/置信/期限）。
- 升级：预判行从"一句话文本"扩展为**结构化条件化预判块**：
  - 方向徽标（看多红/看空绿/震荡灰，附文字）+ 置信 + 多期限格（短/中/长：方向 + 剩余）；
  - 触发条件列表（condition → scenario，折叠）；
  - 验证状态 chip（待验证 date / 命中✓ / 未中✕）。
- 兼容：组件保持**纯 UI**（结构化数据经 props 传入：horizons/conditions/direction/confidence/verification）；文本形态（trace/forecast）沿用旧渲染，不破坏市场洞见等现有用法。改动在组件库，经 `pnpm sync` 同步两端。

### 7.3 板块洞见卡（InsightCard 升级后的使用形态）嵌入两个来源页
- `sector-detail.vue`：行情/K线 之后新增板块洞见卡（该板块当日/近 7 天溯源+预判+验证；严格占位 D4）。
- `traceability.vue`：大盘归因区下方、主因板块处新增板块洞见卡（仅当日主因板块有数据时渲染；无 → "今日大盘未确认主因"文案）。

### 7.4 页面 B · 板块四环日报（modules/market/pages/sector-loop.vue，白卡列表）
- 顶部日期切换：今日 + 回看近 7 天（D2；超 TTL 日期缺源灰置，prediction 仍可查）。
- 大盘归因链路条：有主因板块时显示 `上证 → 主因板块`（链式节点，简化 EventChainGraph）。
- 白卡列表行：板块名 + 当日涨跌（红涨绿跌）+ 来源 tag（风口/大盘主因）+ 溯源短因（仅主因来源）+ 预判方向徽标（置信/到期）+ 验证状态（待验证/命中/未中）。
- 点击跳转分流（见 §2）：风口来源 → sector-detail；主因来源 → traceability。

### 7.5 入口
1. `leaders.vue`：标题行/入口卡「板块预判 · 今日」→ 页面 B。
2. `traceability.vue`：板块洞见卡旁「全部板块研判 ›」→ 页面 B（可选）。
