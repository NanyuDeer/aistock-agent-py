# 动态档位预判 — 影响时长分流（design）

> 日期：2026-09-03 ｜ 范围：aistock-agent-py 生成端（大盘溯源后预判 / 板块预判 / 条件化预判）
> 决策人：组长 ｜ 状态：方案 A（核心）+ B（二期输入增强）纳入本 spec；C（存量治理）视画像数据量再立项

## 1. 背景与问题

四环（溯源 → 预判 → 验证 → 迭代）中，预判环当前**固定要求 short/mid/long 三档并存**（prompt "按短/中/长三档分别输出"），导致：

- 大量**情绪/事件型驱动**（单日资金、突发消息、业绩兑现、题材脉冲）通常在 1-4 周内消化，却被 LLM 硬凑出 mid/long 档 → 凑数档位系统性拉低命中率、稀释画像；
- 画像 `horizon_breakdown` 被噪声污染，失去"该 target 中期是否有逻辑"的参考价值；
- 验证/画像/迭代闭环被无效长期档位占用（2026-09-03 生产中清理的 21+7 档"未来 due 被误判 insufficient/condition 错位"即问题极端形态）。

**用户观察（2026-09-03）**：并非所有情况都会产生中长期影响，多数事件短期内消化，真正影响中长期的情况少。

## 2. 目标 / 非目标

**目标**
1. 让"是否产出 mid/long 档"成为**生成时判定**：情绪/事件型只产 short（或 short 收窄验证），具备可持续产业/政策/资金逻辑才产 mid/long；
2. 缺档**显式留痕**（omitted_horizons），支持产品解释与画像诊断；
3. 档位时间窗不变（5/20/120 交易日），验证/画像/前端零破坏（架构已天然兼容动态 horizons）。

**非目标**
- 不改变验证判定引擎/窗口语义（沿用 [2026-08-31-预判验证-design.md] §10 修复后行为）；
- 不改 Node `allVerified` 判定逻辑（已按"记录实际声明的 horizons"判定，动态自动兼容）；
- C（存量已硬凑的 low-confidence mid/long 档治理）**不在本 spec**，待画像累积后再评估口径。

## 4. 现状盘点（2026-09-03 探索结论）

- `PredictionResult.horizons: list[PredictionHorizon]` 本就动态（≥1 档，validator 只要求非空）→ schema 主结构**无需改类型**；
- Node `appendVerification.allVerified` 遍历 `prediction.horizons` 实际声明档位 → short-only 记录 short 判完即 verified（语义变化为**预期结果**，无需改代码）；
- 前端预测历史/验证组件均按 `due_dates[h]`/verification key **遍历渲染**（v-for），动态档天然兼容；仅个别历史页排序用 HORIZON_ORDER 常量，缺档不影响；
- prompt（`prompts/workers/prediction.py` PREDICTION_PROMPT/PREDICTION_CHAT_PROMPT）现引导"三档并列输出、无法判断时 confidence=low"——需要语义反转；
- due_dates 由 horizon 按交易日 offset（5/20/120）生成，动态档只需对产出档位计算；
- 预筛输入可用字段：大盘预判 `trace.candidates[].category`（溯源候选类别）；板块预判 `sector_snapshot` + 溯源结论。

## 5. 方案 A — 生成端动态档位（核心）

### 5.1 档位白名单策略层（新增 `prediction_horizon_policy.py`）

纯函数策略模块（可单测、可维护、与 LLM 解耦）：

```python
HorizonPolicy = {required: set[Horizon], optional: set[Horizon]}

def infer_horizon_policy(driver_type: str, target_kind: str) -> HorizonPolicy
def classify_driver(evidence_ctx: dict) -> str   # 从候选类别/事件上下文归一到 driver_type
```

驱动类型粗分类表（v1，可扩充；`required` 档 LLM 不可裁——防模型偷懒全 short）：

| driver_type | 典型触发 | required | optional | 依据 |
|---|---|---|---|---|
| `policy_macro` | 产业政策/宏观/利率/地缘 | short, mid, long | — | 政策影响数月传导 |
| `trend_fundamental` | 产业景气拐点/趋势基本面 | short, mid | long | 中长期存疑由 LLM 依证据收窄 long |
| `sector_rotation` | 风格轮动/题材扩散/资金主线 | short | mid | 中期看扩散持续 |
| `event_shock` | 业绩/公告/突发消息 | short | mid | 有基本面成色的可升 mid |
| `transient_market` | 单日异动/情绪脉冲/龙虎榜 | short | — | 默认不产 mid/long |

- `classify_driver` 输入组装点提供（见 5.3）；
- `target_kind` 修正：index 类政策/宏观影响本就长 → policy_macro 的 long 为 required；纯题材 sector 且 driver=transient_market → 仅 short。

### 5.2 Prompt 改造（语义反转）

`prompts/workers/prediction.py`：

- 输入注入：`driver_type`、horizon 白名单（required/optional）、说明"为何只允许这些档"；
- 输出规则：
  - short **必须产出**（白名单内）;
  - required 档必须产出；optional 档**有依据才产**——LLM 需自证（cite 溯源 evidence 中的中期逻辑线索），无据则不产;
  - 未产出的 optional 档 → 写入 `omitted_horizons: [{horizon, reason}]`（reason 须具体，如 "情绪性脉冲、缺乏中期产业逻辑"，禁止空泛）;
  - **禁止越白名单产档**（如 transient_market 不得产 long）;
- 移除"无法判断时 confidence=low 仍输出"的三档并列语言，改为"按逻辑产档、缺档留痕"。

### 5.3 Schema 扩展（`schemas/prediction.py`）

```python
class OmittedHorizon(BaseModel):
    horizon: PredictionHorizonType          # 被省略的档位（mid/long）
    reason: str                              # 省略原因（LLM 产出，归一化校验非空）

# PredictionResult 新增（可选，向后兼容）：
omitted_horizons: list[OmittedHorizon] = Field(default_factory=list)
# 校验（validator）：omitted 与 horizons 互斥（同一档位不得既产出又省略）；
# required 档不得出现在 omitted_horizons（归一化层已强制，此处兜底校验）
```

### 5.4 归一化强制层（防模型漂移，确定性兜底）

- 位置：预判产物后处理（与现有 `_normalize_prediction_validation` / LLM 输出清洗同层）;
- 逻辑：
  1. 对 LLM 输出 horizons：剔除不在白名单内的档位（越界裁剪）;
  2. required 档缺失 → **不硬补**（spec §9 决策③ degraded 已定）：写 `omitted_horizons` 系统留痕 + `prediction_status` 降 `hypothesis`（保留既有产出档验证，宁缺毋滥、可审计）;
  3. short 恒在（异常缺失则按方向补 short）;
  4. 校验 omitted_horizons 与最终 horizons 不重叠、reason 非空;
  5. 输出通过后再进 persistence。

### 5.5 due_dates / 验证 / 画像 / 前端影响

- due_dates：仅对产出档位计算（offset 不变），由现有持久化层对 `horizons` 遍历即可（**已遍历**，无需改）;
- Node 验证：无改动；short-only 记录 short 判完即 verified（预期，画像 mid/long 桶自然稀疏但保真）;
- 画像/统计：`horizon_breakdown` 天然分桶，无需改; A 上线后 mid/long 样本减少属预期（宁缺毋滥）;
- 前端：预测详情展示 `omitted_horizons`（如"未给中长期：情绪性脉冲、缺乏中期产业逻辑"）为可选增强，非阻塞。

## 6. 方案 B — 画像 horizon 门槛反哺（二期输入增强，同 spec）

- `enrich_prediction_input`（skills/prediction_validation.py）扩展：读取 `profile.horizon_breakdown`，
  - 对策略白名单中的 optional mid/long 档：若该 target 该档样本 `n>=3` 且 `hit_rate` 低于阈值（如 `<0.4` 或低于 baseline）→ prompt 附加"该 target 的 {档} 历史印证少，倾向不产";
  - 若该档无样本（n<3）→ 不提示（让数据说话）;
- 纯输入增强，不动 schema/验证; 依赖画像数据量（2026-09-03 起画像才开始产出），生效需要时间;
- 上线节奏：A 落地且画像 mid/long 桶积累 ≥3 样本的 target 出现后启用。

## 8. 测试要点

- 策略表：5 类 driver × index/sector/stock 组合 → 白名单断言；required 恒含 short;
- schema：omitted 与 horizons 互斥；required 档出现在 omitted → 抛;
- 归一化：transient_market 输入 LLM 输出含 long → 裁剪; 全 short 产物 short 恒在;
- prompt：policy_macro fixture 产物含 short/mid/long; event_shock 产物可仅 short+omitted_mid;
- run_predict e2e：dynamic fixture（today 事件型）→ 落库 horizons=[short]、due_dates 仅 short、omitted_horizons 含 mid/long;
- Node 侧回归：short-only 记录 PUT 一次即 verified（internalRouter/PredictionRecordService 既有测试覆盖断言不破坏）;
- B：enrich 输入 profile.horizon_breakdown 低命中 → prompt 附加提示（断言 input 含抑制语句）。

## 9. 风险与待决策

1. **required 档缺失兜底**（P4 前定）：选项 ① 归一化自动按主方向补 required 档（保证一致性，但可能引入半凑数档，弱化"不硬凑"初衷）；② 记录级 `status=insufficient` 语义扩展（复杂）；③ required 档缺失时该条预判整体标记 `degraded`（保留既有档位验证，产品端明示）。**已定 ③ degraded**（组长确认，2026-09-03 Task4/caf7e49 落地）：required 缺档不硬补凑数——归一化层写 `omitted_horizons`（reason="依据不足未产出（系统归一）"留痕）+ `prediction_status` 降为 `hypothesis`（degraded 语义：保留 short 等既有产出档验证、宁缺毋滥、可审计）。
2. **收窄过度**：LLM 可能倾向全 short（省事）→ 由 required 机制兜底（policy_macro 必须 mid+long），短期观察 P3/P4 fixture 覆盖分布，必要时把 optional 降为 required 档的规则上调。
3. **画像 mid/long 样本骤减**：预期结果; B 阶段门槛（n>=3）依赖新数据积累; 在此前画像 mid/long 桶解释性降低——产品口径上"mid/long 只对真有中期逻辑的 target 产出"，属设计意图。
4. **存量记录**：3.0 存量（已硬凑三档）不受影响、不迁移; C 治理另行立项。
5. **driver 分类质量**：`classify_driver` 依赖候选类别标签质量; 未知类别回落 `transient_market`（保守，宁少产 mid/long）。

## 10. 兼容与验收口径

- schema_version 保持 `"3.0"`（向后兼容新增可选字段，不升版本；`omitted_horizons` 缺省空）;
- 验证/画像/迭代/前端消费方：验证零改动; 前端 omitted 展示为可选;
- 验收：P1-P6 测试全绿 + 服务器部署后对 1-2 个**事件型触发**记录观察产物 horizons=[short]+omitted（对照 1-2 个政策型=三档），画像 horizon 桶分布符合 driver 性质。
