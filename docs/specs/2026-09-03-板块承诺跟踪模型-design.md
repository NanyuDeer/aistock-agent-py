## 1. 背景与问题

板块预判每天 19:30 对当日热点榜板块批量生成预测，存在三个结构性缺陷：

- **P1 跨日结论冲突**：同一板块连续多日上榜时，每天从零生成一份独立预测；short 窗口（5 交易日）重叠期方向可相反（今天看多、明天因当日大涨转"高位分歧看空"），页面并存互相矛盾的承诺。

- **P2 验证判定太晚**：条件化预判的 condition 触发与否只在**到期日**（due，按 horizon 固定 5/20/120 交易日）一次性判定——此时"条件 + 预判走势"都已走完，条件亮起时刻滞后，无法在条件出现时就进入"待验证"并驱动下一步。

- **P3 验证日定死**：承诺兑现窗口绑定固定档位偏移（+5/+20/+120），既不接受 LLM 对时效的表述（"事件后 3 日"），也无法处理"预判提前兑现 → 及时进入下一步"的场景。

## 2. 第一性定位与目标

**板块预判 = 可证伪的短线跟踪承诺**（讨论稿确认）：

1. **决策锚**：给用户"该盯什么板块、多头逻辑是否还成立"的可操作预期（带触发条件与幅度的承诺，非方向玄学）
2. **验证闭环的前提**：只验证"说出来的可检验的话"，命中率积累可信度
3. **迭代反哺的原料**：命中率/失效原因回流驱动溯源-预判-验证-迭代闭环

由定位推出的推论（本 spec 全部机制的裁决框架）：

- 预判是**短窗口、会过期、逐日滚动更新**的观点，不是长期真理

- 板块多日预测 = 同一对象的**连续版本**（研报跟踪模型）：**验证按报告版本归档、谁到期验证谁**，条件变化不产生验证歧义

- 验证对象是"承诺"，承诺产生即绑定验证义务，义务不随后续新预测消失

### 2.1 目标（验收口径）

- G1 同板块同档位在任意时刻最多一个活跃承诺（无并存冲突承诺）

- G2 承诺开出后必进终态（兑现 / 未中 / 到期过期 / 显式终止之一），有界不膨胀

- G3 条件触发在**到期前**即可被逐日扫描点亮，点亮后该路径进入"待验证"

- G4 提前兑现的承诺可及时关闭，允许该档位**在每日任务窗口内**立即开新承诺（不等原窗口满）

- G5 显式终止（翻转）的旧承诺照常履行验证义务（终止时点判定入验证记录），不可追溯丢失

- G6 前端板块四环不再以日期为主维度（方向 C）

### 2.2 非目标（YAGNI）

- 不做盘中实时检测/盘中预测链路（提前兑现由每日任务消化）

- 不做条件层跨日 diff/一致性比对（条件层只服务当期验证锚点）

- 不做跨板块/跨市场的联合预测

- 不改变大盘/个股的现有预测与验证流程（本 spec 只约束板块承诺链；字段预留可平移到大盘，但不在本期实施）

## 3. 核心概念与承诺状态机

### 3.1 概念

- **承诺（commitment）**：一条"板块 × 档位 × 报告日期"的预测单元，带方向、幅度、LLM 输出的承诺兑现窗口、触发条件集。落库层=现有 prediction 记录内按 horizon 拆出的子单元（horizon key）。

- **承诺链**：同一板块同一档位按时间排序的承诺序列（上一承诺终态后允许下一承诺）。展示为详情页时间线。

- **活跃承诺**：尚未进入终态的承诺。约束：同板块同档位活跃承诺数 ≤ 1（G1）。

### 3.2 档位承诺状态机

```
fresh(已开未触发)
  │  每日触发扫描命中该档某条件（且该条件路径 anchor 方向存在）
  ▼
condition_hit(条件点亮·待验证)
  │  走势验证：提前兑现 / 窗口到期判定 / 显式终止(翻转)
  ▼
terminal:  satisfied(兑现) | missed(未中) | expired_unhit(未触发过期) | terminated(显式终止)
  全部 terminal → 承诺归档 → 该档位允许开新承诺
```

状态说明：

| 状态             | 含义            | 进入条件                        | 归档去向                  |
| -------------- | ------------- | --------------------------- | --------------------- |
| fresh          | 已开、条件未触发      | 新预测落库                       | —                     |
| condition\_hit | 条件点亮、路径待验证    | 逐日触发扫描命中（判定见 §5.2）          | —                     |
| satisfied      | 提前/按时兑现       | 走势在窗口内达 anchor 方向+threshold | 验证记录 hit              |
| missed         | 未中            | 窗口期满未达                      | 验证记录 miss             |
| expired\_unhit | 条件一直未触发而窗口自然满 | 开承诺起算窗口满仍 fresh             | 验证记录 insufficient/未触发 |
| terminated     | 显式终止（翻转通道）    | 新信息推翻未决承诺                   | 终止时点判定入记录（§5.4），不豁免   |

### 3.3 承诺窗口（G4/P3 的载体）

- **窗口来源**：LLM 每档输出 `due_hint`（自然语义，如"3\~5 个交易日""事件落地后 3 日"），系统转交易日数值 `window_days`（解析规则见 §6.1）；解析失败回退档位默认偏移（5/20/120）。

- **计时起点**：**开承诺日起算**（用户拍板）。即承诺开出即开始计窗口；窗口满时无论是否触发均进入终态判定。

- **提前兑现**：窗口内任意交易日收盘达该档 anchor 方向 + threshold（如短线上探 ≥ +3%），即 satisfied，承诺关闭，档位释放（当日任务即可新开）。

- **到期判定**：window\_days 满且未 satisfied → 按 \[due, due+3] 窗口判定（沿用现有 run\_once 引擎语义，仅 due 改为 LLM 窗口解析结果）；未触发（fresh）到满期 → expired\_unhit。

> 说明：计时起点选"开承诺日"而非"点亮日"，是把窗口作为承诺自身的时效承诺（用户 09-03 拍板），避免条件迟迟不触发导致承诺无限挂起。

## 4. 承诺生命周期规则

1. **新开前提 = 旧承诺已结清**（R1）：同板块同档位上一承诺处于 terminal 才允许新开；不存在"覆盖旧承诺再开"的路径。翻转为唯一例外，见规则 4。
2. **按档位独立**（用户拍板）：short 提前兑现后即使 mid 未决也可开新预测；新预测的**档位白名单 = 该板块已终态档位**（复用动态档位机制：`required`/`optional` 注入 LLM，未决档位不出现在本次输出）。
3. **每日任务推进而非每日重造**（P1 的消除方式）：19:30 任务先跑承诺状态机（点亮/提前兑现/到期/失效判定），再决定各板块哪些档位可开新；可开档位集合为空 → 该板块不生成新预测，页面呈现"延续态"。
4. **翻转通道（显式终止）**：新信息足以推翻**未决**承诺时，终止旧承诺（原因入档）并开新承诺。判定主体=LLM（新预测 prompt 注入旧承诺摘要，输出 `stance_relation=reversal` + `termination_reason` 才允许翻转；`relation ∈ fresh/continuation/upgrade/downgrade/reversal`）。
5. **终止不免验证**（G5）：terminated 承诺在终止日立即按当前事实判定（方向已逆 → missed；已达部分目标 → satisfied；无法判定 → insufficient 注明提前终止），与自然到期同样入库画像。旧承诺不因新承诺开出而失去验证义务。
6. **条件层不参与跨日 diff**：conditions 互斥路径是当期战术推演，只服务当期验证锚点；跨日一致性只在基准层（horizons 档）通过规则 2/4 表达。

## 5. 验证两段式（G3/P2 的载体）

### 5.1 两段时刻

| 段         | 时刻                         | 判定对象                | 输出                            |
| --------- | -------------------------- | ------------------- | ----------------------------- |
| t1 条件触发扫描 | 逐日 16:00（交易日）              | 活跃承诺各条件是否被当日/近期事实命中 | condition 点亮 → condition\_hit |
| t2 走势兑现判定 | 提前兑现检查（逐日 16:00） + 窗口满到期判定 | 已点亮路径的方向/幅度 vs 实际   | satisfied / missed            |

### 5.2 条件触发判定（t1）

- **自动判定（首选）**：条件携带数值 anchor（`anchor.threshold/metric/direction`）→ 用当日收盘读数比对（读取扩展为逐日滚动窗口：开承诺日至今的 kline/量能，判定"触发日"）。

- **LLM 辅助（用户拍板，自动不可判时）**：非数值条件（无法 anchor 化，如"站稳前高并回补缺口"）→ 由 LLM 读取该板块开承诺日至今的行情快照 + 条件原文，判定 `{hit: true, hit_date, evidence}`。该任务与验证环解耦、独立小批量 cron（与 16:00 同批，仅在存在不可自动判的活跃承诺时触发）。

- **点亮持久化**：condition 级新增 `condition_hit: {hit, hit_date, source: auto|llm, evidence} | null`。点亮后不可回退（除非显式终止重开）。

### 5.3 走势兑现判定（t2）

- 提前兑现：逐日 16:00 对 condition\_hit 的承诺检查是否已达 anchor threshold（沿用现有 `_verify_horizon` 的方向符号/幅度判定内核，改为**滚动检查**而非等 due）。

- 到期：window\_days 满后按 \[due, due+3] 一次判定（若尚未提前 satisfied/missed）。

- 现有 run\_once 引擎（16:00、wait\_window、grade）保留内核，改造点为：触发点亮提前、due 由窗口解析替代、状态机终态分流。

### 5.4 显式终止判定（翻转通道的验证义务）

terminated 承诺在终止日做一次"时点判定"：按当日收盘与 anchor 比对，输出 satisfied/missed/insufficient 之一并标注 `termination_reason`，入画像；不等待原窗口。

## 6. 生成侧改造（agent-py）

### 6.1 schema 变更（prediction.py）

`PredictionHorizon` 新增：

```
due_hint: str = Field(default="", description="该档承诺兑现窗口的自然语义表述（如 “3~5 个交易日”/“事件落地后 3 日”）；系统据此解析 window_days，解析失败回退档位默认偏移")
window_days: int | None = Field(default=None, description="程序化承诺窗口（交易日数），由 due_hint 解析产出；None=未解析回退默认档位偏移")
```

`PredictionResult` 新增（跨日关系，prompt 注入旧承诺后输出）：

```
stance_relation: Literal["fresh", "continuation", "upgrade", "downgrade", "reversal"] | None = None  # 相对上次同板块同档承诺的关系；首开/无历史 = fresh
termination_reason: str = Field(default="", description="relation=reversal 时必填：旧承诺失效的新证据/失效条件；非翻转不得填写")
prev_prediction_ref: {date, horizon, direction, target} | None  # 上次承诺摘要引用（系统注入，LLM 不产）
```

### 6.2 prompt 变更（prediction.py 双 prompt）

- horizons 段：新增 due\_hint 输出说明（语义窗口、禁整句、单位交易日表述如"5 个交易日"）。

- 输出前注入"上次承诺摘要"段（系统注入：近 30 天同板块最近一次预测的 {date, 每档 direction/target/label、验证结果(若已终态)}）；要求 LLM：a) 可开档位才产；b) 若方向相对上次翻转 → `stance_relation=reversal` + 写 termination\_reason（新证据），不满足"新证据充分"则保持原方向并 relation=continuation/upgrade/downgrade。

- 旧承诺状态摘要同时约束"未决不重开"与"翻转需理由"，是 P1 的生成侧核心。

### 6.3 归一化层（prediction\_service）

- `_sector_prediction_core`：预测前查询"该板块各档位活跃承诺"→ 组装档位白名单（仅终态档）与上次承诺摘要注入 prompt；预测后校验输出档位 ⊆ 白名单 ∪ 无历史档位（越界档位丢弃并 omitted 留痕）。

- 翻转判定依据 `stance_relation`，reversal 时把旧承诺标记 terminated（调 Node 更新）并写终止原因；非 reversal 而方向相反 → 视为模型违规，拒绝该档（回退 continuation 姿态需重试或丢弃）。

## 9. API 变更（sector-insight）

现状：`/sector-insight/:date` 按日期聚合当日热点 + 当日预测。新形态（方向 C 的前提）：

- 提供"板块 × 当前承诺"聚合：`GET /sector-insight/commitments?date=...` 返回板块清单，每板块带**各档活跃承诺最新状态**（fresh/condition\_hit/terminal 近 N 日）+ 当日有无新开/翻转事件 + 指向详情页的承诺时间线句柄

- 兼容旧 `/sector-insight/:date`（报告页/历史回看仍按日）

## 10. 前端（app-frontend 板块四环方向 C）

展示主体 = 板块卡列表，每卡承载该板块**当前活跃承诺的最新状态**（而非当日新预测）：

```
┌────────────────────────────────────┐
│ 创新药   [新] 今日开   09-03        │  ← 状态行：新/延续中·第N日/已点亮/已兑现/未中
│ 溯源：医保谈判预期催化放量          │
│ ┌ 短期 5日 │ 若[量能≥600亿] 则[上探+3%]  ✓已点亮(09-03) 详情▾
│ │ 承诺兑现窗口至 09-10 · 待验证       │
│ └ 中期 20日 延续中·第5日             │
│ [查看承诺时间线 →]                  │
└────────────────────────────────────┘
```

排序：新承诺（今日新开/翻转）优先 → 进行中按剩余窗口 → 近 7 日终态折叠；无任何承诺的当日热点板块仍展示（溯源 + "待预判"空态或说明未开原因）。
详情页（sector-detail）：新增"承诺时间线"区块：开承诺 → 条件点亮 → 提前兑现/到期/翻转的完整链（每节点日期+一句话+验证结果）。

## 12. 风险与开放问题

- R1 **due\_hint 解析鲁棒性**：LLM 自然语义 → 交易日数值，需解析器+回退档位默认；歧义表述（"约一周"）统一归一。

- R2 **LLM 辅助触发判定的可靠性**：自动不可判条件由 LLM 判定，可能误点亮——以 evidence 留痕 + 允许翻转纠正；初期仅对"自动可判"条件开点亮，LLM 辅助作为增强（上线灰度）。
