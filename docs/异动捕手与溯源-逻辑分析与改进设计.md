> 生成时间：2026-08-01
> 范围：aistock-agent-py（alert agent + stock_trace consumer）+ aistock-app-api（stock-trace 模块 + cron）

## 一、整体逻辑全貌

异动捕手与溯源是**两个独立但联动的系统**：

| 系统 | 触发模式 | 核心组件 |
|------|---------|---------|
| 异动捕手（alert） | 被动响应 | alert agent（3 子 Agent + Master） |
| 个股异动溯源（stock_trace） | 事件驱动 | PriceTriggerDetector + Redis Stream + StockTraceConsumer |

## 二、异动捕手（alert agent）

### 2.1 架构

**文件**：`aistock-agent-py/src/aistock_agent/agents/workers/alert.py`

Phase 6 重构版本（2026-07-10），3 个子 Agent 并行 + Master 汇聚：

```
                ┌── 资讯情报 (quick_think) ──┐
                │   查新闻找异动原因          │
symbol + cycle ─┼── 盘口风控 (deep_think) ───┼── Master (deep_think) ── 双层输出
                │   分析盘口+资金面，判真实意图 │   汇聚融合 + 操作建议    (display_report +
                └── 图谱发散 (quick_think) ───┘                           podcast_brief)
                    用知识图谱找补涨标的
```

### 2.2 触发方式（4 种 trigger_source）

| trigger_source | 入口 | 写 DB | 缓存 | 场景 |
|---------------|------|-------|------|------|
| `user` | `GET /api/agent/briefing/alert?symbol=&cycle=` | ❌ | ✅ | 前端用户主动查询 |
| `manual` | `POST /api/agent/briefing/morning/trigger` 系列 | ❌ | ✅ | 管理员手动触发 |
| `scheduler` | scheduler.py 调用 | ✅（symbol 作 user_id） | ✅ | 定时任务（**当前未注册**） |
| `stock_trace` | `POST /api/agent/trace/stock/trigger`（Node 调用） | ✅（含 trace_id） | ❌ | 溯源链路调用 |

### 2.3 cycle 参数

| 值 | 标签 | 含义 |
|----|------|------|
| `short` | 短线（1-5天） | 短线异动研判 |
| `mid` | 中线（1-4周） | 中线异动研判 |
| `long` | 长线（1-6月） | 长线异动研判 |

### 2.4 决策：不添加定时任务

**用户决策（2026-08-01）**：alert agent 保持被动触发，不添加 cron。

**理由**：
- 异动捕手的本质是"针对特定股票的深度研判"，需要明确的 symbol 输入
- 定时扫描全自选股池 token 成本高（每次 3 子 Agent + Master）
- 盘中实时性已由 stock_trace 事件驱动链路覆盖
- 收盘后的总结已由 review 复盘流水线覆盖

## 三、个股异动溯源（stock_trace）

### 3.1 完整事件驱动链路

```
┌─────────────────────────────────────────────────────────────────────┐
│ Node.js (aistock-app-api)                                            │
│                                                                      │
│  PriceTriggerDetector (setInterval 5s)                              │
│    ├─ 仅在 A股交易时间运行 (isAShareTradingTime)                      │
│    ├─ 拉取所有自选股行情 (TencentQuoteService.getBatchQuotes)         │
│    ├─ 涨跌幅 ≥ 7% (PRICE_TRIGGER_PERCENT=7) → 触发                   │
│    └─ StockTraceService.processPriceFact                             │
│         ├─ 写 PostgreSQL:                                            │
│         │   ├─ stock_trace_events (事件主表, 含 event_status)         │
│         │   ├─ stock_trace_trigger_revisions (修订版本)               │
│         │   └─ stock_trace_signals (信号记录)                         │
│         ├─ StockTraceJobService 写 job + 事务性 Outbox               │
│         └─ 发布到 Redis Stream "stock-trace.jobs"                     │
│                                                                      │
│  StockTraceAlertOrchestrator                                        │
│    ├─ pushSeverityUpgrade: 严重度升级时 WebSocket 推送               │
│    └─ pushConfirmedMajorCause: 确认主因后推送                        │
└─────────────────────────────────────────────────────────────────────┘
         ↓ Redis Stream (stock-trace.jobs)
┌─────────────────────────────────────────────────────────────────────┐
│ Python 独立进程 (stock_trace_consumer.py)                            │
│                                                                      │
│  StockTraceConsumer.run_forever()                                   │
│    ├─ ensure_group: 创建 consumer group (幂等)                       │
│    ├─ consume_once:                                                  │
│    │   ├─ xautoclaim: 先认领超时 pending 消息（3s 空闲）              │
│    │   ├─ xreadgroup: 阻塞读取新消息 (block 1000ms)                  │
│    │   └─ _consume_message:                                          │
│    │       ├─ report_job(processing)                                 │
│    │       ├─ StockTraceWorker.analyze(event_id, revision, version) │
│    │       │   ├─ NodeClient.get_analysis_context (冻结快照)         │
│    │       │   ├─ LLM with_structured_output (deep_think)            │
│    │       │   ├─ _strip_post_window_market_references (剥离窗外)    │
│    │       │   └─ validate_stock_trace_result (校验)                 │
│    │       ├─ NodeClient.write_result → Node 校验后发布 Artifact     │
│    │       ├─ 成功: xack 确认                                         │
│    │       ├─ SNAPSHOT_NOT_READY: 不确认, 等待 pending reclaim        │
│    │       └─ 失败: report_job(failed), 重试 3 次后进死信队列 DLQ    │
│    └─ run_forever: 无限循环, 异常 sleep 1s 重试                      │
└─────────────────────────────────────────────────────────────────────┘
```

### 3.2 关键参数

| 参数 | 值 | 说明 |
|------|-----|------|
| `PRICE_TRIGGER_PERCENT` | 7 | 涨跌幅触发阈值（%） |
| `PRICE_RULE_VERSION` | `price-v1` | 规则版本 |
| `DETECTOR_INTERVAL_MS` | 5000 | 轮询间隔（5 秒） |
| `stock_trace_redis_url` | `redis://localhost:6379/2` | 独立 Redis DB（与主服务 db=1 隔离） |
| `stock_trace_consumer_group` | `stock-trace-workers` | consumer group 名 |
| `stock_trace_pending_claim_idle_ms` | 3000 | pending 消息认领空闲阈值 |
| `stock_trace_max_attempts` | 3 | 最大重试次数 |

### 3.3 数据隔离设计

- **Redis DB 隔离**：stock_trace 用 db=2，主服务用 db=1，避免 Stream 与缓存互相干扰
- **trace_id 隔离**：alert agent 在 `trigger_source="stock_trace"` 时，写入 DB 的 content 包含 `trace_id` + `schema_version: "stock_trace.v1"`，与普通 alert 报告区分
- **event_id 隔离**：stock_trace_events 表以 event_id 为主键，同日不同事件分别保存

## 六、逻辑完善度评估

### 6.1 完善的部分 ✅

1. **alert agent 架构完整**：3 子 Agent 并行（资讯情报/盘口风控/图谱发散）+ Master 汇聚，支持双层输出（display_report + podcast_brief）
2. **stock_trace 事件驱动链路设计严谨**：Outbox 模式保证消息不丢 + 至少一次消费 + 死信队列 + 幂等校验 + 窗外数据剥离
3. **异动检测阈值明确**：7% 涨跌幅，仅在交易时间运行，避免无效触发
4. **实时推送机制齐全**：WebSocket（alert-channel）+ 严重度升级推送 + 主因确认推送
5. **数据隔离设计**：trace_id / event_id / symbol 作为 user_id，与普通 alert 报告区分
6. **双层输出兼容**：report_parser 兼容 schema_version 1.0/2.0，旧报告无需迁移

### 6.2 不完善的部分 ⚠️

1. **stock_trace_consumer 无 PM2 部署配置**：aistock-agent-py 目录下没有 ecosystem.config.json，只有 Dockerfile；aistock-app-api/deploy/ecosystem.config.json 只部署了 app-api。**溯源 consumer 在华为云服务器上可能根本没运行**。
2. **agent-py 主服务也无 PM2 配置**：当前只有 Dockerfile，但华为云服务器用 PM2 管理（与 app-api 一致），缺少 ecosystem 配置
3. **stock_trace_consumer 独立进程不便重启**：用户反馈"如果是独立的，那么不方便每次重启"
4. **stock_trace 的 7% 阈值偏保守**：盘中分时异动（如 5% 快速拉升）可能漏掉，但这是业务决策，暂不调整

## 七、改进方案：stock_trace_consumer 集成到 agent-py 主进程

### 7.1 用户决策

> "stock_trace_consumer 独立进程能不能直接改到 agent-py 里面，因为如果是独立的，那么不方便每次重启"

### 7.2 方案对比

| 方案 | 描述 | 优点 | 缺点 |
|------|------|------|------|
| **A. 集成到 lifespan** | 在 main.py lifespan 中用 `asyncio.create_task` 启动 consumer | 一次部署、一次重启；无需额外进程 | consumer 异常可能影响主服务；共享事件循环 |
| **B. 独立进程 + 统一 ecosystem** | agent-py 下新增 ecosystem.config.json，含 2 个 app | 进程隔离；pm2 统一管理 | 需重启 2 个进程（pm2 restart all 很简单） |
| **C. 开关控制集成** | 方案 A + 环境变量开关 `STOCK_TRACE_CONSUMER_ENABLED` | 灵活：开发关闭、生产开启 | 实现稍复杂 |

### 7.3 推荐方案：C（开关控制集成）

**理由**：
- 满足用户"方便重启"的核心诉求（一次 `pm2 restart aistock-agent` 即可）
- 开关控制避免开发环境意外启动 consumer
- consumer 的 `run_forever()` 已是 async，用 `create_task` 不会阻塞主事件循环
- 异常隔离：`run_forever` 内部有 try/except + sleep 1s 重试，不会因单次失败崩塌

### 7.4 实现要点

#### 7.4.1 配置项（config.py 新增）

```python
# stock_trace consumer 是否在主进程内启动（true=集成, false=独立进程）
stock_trace_consumer_enabled: bool = True
```

#### 7.4.2 main.py lifespan 改造

```python
@asynccontextmanager
async def lifespan(_app: FastAPI) -> AsyncIterator[None]:
    # ... 现有 RedisPool / HttpClientPool / scheduler 初始化 ...

    # 启动 stock_trace consumer（集成模式）
    consumer_task: asyncio.Task | None = None
    if settings.stock_trace_consumer_enabled:
        try:
            from aistock_agent.workers.stock_trace_consumer import StockTraceConsumer
            from aistock_agent.services.redis_pool import RedisPool as _RP

            # 注意：consumer 用独立的 stock_trace_redis_url
            # 需要初始化第二个 Redis 连接（或复用主连接，取决于 RedisPool 设计）
            stock_trace_redis = await _init_stock_trace_redis()
            consumer = StockTraceConsumer(stock_trace_redis)
            consumer_task = asyncio.create_task(consumer.run_forever())
            logger.info("stock_trace_consumer_started_in_process")
        except Exception:
            logger.error("stock_trace_consumer_start_failed", exc_info=True)

    yield

    # 关闭：先取消 consumer task
    if consumer_task is not None:
        consumer_task.cancel()
        try:
            await consumer_task
        except asyncio.CancelledError:
            pass

    # ... 现有 shutdown 逻辑 ...
```

#### 7.4.3 Redis 连接池问题

**当前问题**：`RedisPool` 是单例，主服务用 `redis_url`（db=1），consumer 用 `stock_trace_redis_url`（db=2）。集成后需同时持有两个连接。

**解决方案**：让 consumer 在 lifespan 中独立初始化一个 `aioredis.Redis` 实例，不经过 `RedisPool` 单例：

```python
async def _init_stock_trace_redis() -> aioredis.Redis:
    return aioredis.from_url(
        settings.stock_trace_redis_url,
        max_connections=settings.redis_max_connections,
    )
```
