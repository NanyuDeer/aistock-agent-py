九层到底各干什么：用大白话说一遍

这里的“9 层”不是 9 个部门、也不是 9 套服务，而是同一条流水线上的 7 道工序 + 2 个全厂共享设施。7 道工序是 GT → GP → GR → GJ → GC → GE → GO；2 个共享设施是底部的 GM（台账）和左下的 GX（工具箱）。

层大白话：它负责什么上游从哪来下游给谁一句话记住
GT 触发决定“什么时候、因为什么跑一次”：到点（早/午/晚）、出事（异动/新闻/失效）、用户点了、账本到期要复查。定时器 / 事件流 / 前端 / M3 的复查时间O1 编排门铃：不负责分析，只负责叫人
GP 感知把原始世界搬进来，并且只搬一次：行情、资金、指数、新闻、公告、研报、实体归属、用户自选与持仓，全部变成带来源的证据。O1 派活M1 证据账本采购员：按清单买齐，记清从哪买的
GR 研究六条研究线各算各的：趋势、风口/板块、事件传导、基本面、个股异动归因、节奏情绪。它们允许互相矛盾，也会互相修正（板块强会改个股结论，龙头异动也会反过来改板块强弱）。M1 的证据切片M2 论点账本六个分析师：各写各的论点，不许互相抄结论
GJ 研判把六个分析师关进一个会议室：J1 说看多理由，J2 专门唱反调并给失效条件，J3 消解冲突、该降权就降权，J4 写下一份最终结论（方向 / 置信度 / 什么时候复查）。M2 的论点 + C1 的校准先验M3 研判账本投委会：只出一份纪要，但反方意见必须留档
GC 校准负责“越用越准”：C1 用历史命中率校准今天的置信度；C2 到期（due + 3）拿真实行情回填命中/未命中；C3 把错误样本归纳成方法版本，写进方法库，再回灌研究。M3 的历史研判J4（先验）、M4（方法版本）质检 + 复盘：不生产结论，只修正生产结论的方法
GE 表达把同一份结论换几种说法：播报扩写成叙述、个股页写成研判卡、推送只写变化、对话写成带引用的回答、选股写成榜单。可以换语气，不许加新结论。M3 的 judgmentGO 出口翻译 + 排版：同一份原文，出五个版本
GO 出口用户真正看到的六个地方：首页结论、个股页、事件页、播报/推送、对话、选股页。只渲染，不推理；页面上每个结论都能点回 judgment 和证据。GE 渲染结果 / M3 只读投影用户柜台：只负责把货摆出来，不负责生产
GM 记忆 / 治理六本共享台账：M1 证据、M2 论点、M3 研判、M4 方法、M5 知识图谱与研报、M6 治理指标。任何一层都能按需读切片、写新增，谁也不能私藏一份自己的数据。所有层的写入所有层的读取共享台账：全厂只有一本账，不是每人一个 Excel
GX 工具带24 个 LangChain 工具，把 app-api 的能力包成统一形状（数据 + 来源 + 质量 + 错误）。Agent 不直连外部数据源，也不允许“查不到就当 0”。P / R 节点的调用P / R 节点公共工具箱：水电煤统一接，不许私拉电线

它们怎么联系？记一条竖线、两条横带就够了：竖线是 T → O1 → P → M1 → R → M2 → J → M3 → E → U，一条业务从按门铃到上柜台；两条横带是 GM 和 GX，横穿所有工序。再记三句话：数据只取一次（P 写 M1，后面都读）、结论只写一次（J4 写 M3，全站引用同一个 judgment_id）、出口只渲染（E/U 不重新分析）。

所以“9 层”不是把系统切碎，而是把一件事情的 responsibility 摆清楚：谁取数、谁研究、谁拍板、谁质检、谁说话、谁给用户看。同一张 LangGraph 里，不同功能只是启动不同的节点子集。

以前

市场 / 消息 / 风口 / 节奏各调一个接口；标签由前端按字段拼；播报只读 brief。四个格子之间没有共享证据。

现在

四个格子是 M1/M2 的四个投影；每个标签背后是一条带 evidence_id 的 claim；播报读 M3 的 judgment_id。

布局、文案、跳转都不变；卡片增加“来源节点 / 失效条件 / 证据条数”；degraded 从“证据不完整”细化为“哪本账缺证据”。

03

AI 对话

对话形态不改造：还是问答 + 卡片 + 推理过程 + 深度分析 + 追问。变的只是“回答从哪来”——从某一个 worker 自己算，变成读同一本账。

代码核实 · 2026-11-22
  • 前端：aistock-app-frontend/src/pages-sub-app/chat/index.vue，支持大盘 / 个股 / 资金 / 对比 / 新闻 / 科普等问法；有 ReasoningPanel（推理过程）、CardRenderer（结构化卡片）、DeepSummaryCard（深度总结）、token 用量、深度分析入口、追问。
  • 后端现状：aistock-agent-py 是 LangGraph StateGraph，START → supervisor → intent_router，路由到 10 个可路由 worker：morning / stock / sector / event / wind_leader / broadcast / general / hot_burst / alert / trend_score，执行后直接 END。
  • 另有 5 个仅调度 worker：review / rhythm_master / midday / midday_broadcast / iterate，不在对话路由表里。
  • 关键限制：一次对话只进一个 worker，worker 之间不共享 evidence / judgment；同一个问题问两次、或换个入口问，可能得到两套口径。
  • 没有的东西：当前没有“固定四段式回答”这种实现；目标 E4 也不规定回答结构，只规定“必须引用 judgment_id / evidence_id”。

真实节点链路 · AI 对话

这是六张图里节点最全的一张：对话可以按意图触及任意研究子图，但每个子图仍然只写自己那类 claim。

19 个功能节点 + 4 本账
主链路研究联动C1 校准账本读写M5 只在这一张与个股详情里出现
本功能调用工具：quote · kline · flow · market · news · announcement · research · forecast · institution · graph · event_entity · profile · trace · prediction
与总图的共性：同样走 O1 → P* → M1 → R* → M2 → J1/J2 → J3 → J4 → M3，只是出口换成 E4 → U5；E4 不产生新结论，只读账本。
本功能特有：多一个 P4（自选 / 持仓 / 画像进入同一次 run）；多一本 M5（R4 读研报与实体）。科普 / 纯概念问题由 O1 判为轻档，只走 E4，不启动研究子图——这是唯一允许跳过 R/J 的合法路径。
  1. T3 用户提问。问题带 subject（个股 / 板块 / 事件 / 大盘）和意图，统一进 O1，不再由前端决定调哪个接口。
  2. O1 判档位。“什么是市盈率”这类纯概念问题 → 轻档，直接 E4；“算力还能追吗” → 重档，扇出多个研究子图；“帮我看看宁德时代” → 个股档。
  3. P1-P4 并行取证据。P4 把自选、持仓、历史偏好带进同一次 run，让回答带用户上下文；四份证据统一写 M1。

10

Agent 还能怎么改进

下面 8 条不是“再加功能”，而是让现有 Agent 更像一个可验证、可复盘的分析师。每条都对应架构里的一个已有位置，不需要推翻重来。

  1. 让“证据不足”成为合法结论，而不是失败。现在大盘溯源要 status = completed、schema 2.0、summary / details 齐全才显示，否则整页空态；这等于逼模型“必须编一个主因”。目标态应允许 hypothesis / insufficient 正常落 M3，页面明确写“证据不足，暂不下结论”，并列出缺哪类证据。对应：J4 状态位 + M3 落账。
  2. 把验证闭环真正做出来。C2 到期（due + 3）自动回填真实走势，C3 把“错在哪”归成错误类型（方向错 / 幅度错 / 时点错 / 归因错），写进 M4；C1 才有真实命中率可用。没有这一环，置信度永远只是模型自评。
  3. 每条 claim 必须可证伪。选股的 signals.invalidation 现在只是文本；应升级成“指标 + 阈值 + 观测窗口”，例如“收盘跌破 20 日线”或“板块热度掉出前 10”。到点由 C2 / T4 自动检查，触发后进提醒，而不是等人读出来。对应：M2 claim + E3 推送。
  4. 工具返回必须带 provenance / quality / error，空结果不许归零。GX 的 24 个工具统一信封；取不到就说 failed 并写原因，让下游知道“这是没数据”还是“数据是 0”。这条能直接减少“看起来有结论、其实没证据”的错误。
  5. 记忆按切片读，不要每次塞全量上下文。M1 只给下游该标的、该板块、该时段的证据投影；M2 只给相关 claim；对话走 M3 只读投影。这样既省 token，也避免模型被无关证据带偏。对应：M1 / M2 / M3 的投影接口。
  6. 反方不能只列观点，要带触发条件。J2 现在可以写“机构热门未进前 20”，但更该写“如果 3 日内仍没进前 20，则下调一档”。反方有了阈值，J3 才能真的降权，C2 才能验证反方对不对。
  7. 给每次 run 设预算与降级路径。O1 按档位分配工具调用数与超时；证据不完整时像晨报一样明示 missing_sources，先出“低置信版本”，而不是整页失败或无限重试。对应：O1 + E1 的降级展示。
  8. 做离线回放评测，再上线。用 M3 里历史 judgment + 当时的行情做回放，按置信度分层算命中率，比较改提示词 / 改阈值前后的差异；结果写 M6。这样“分析变准了”有数字，不靠感觉。
优先级建议：先做第 2 条（验证闭环）和第 3 条（可证伪），因为没有它们，后面所有“更准”都无法证明；再做第 1、4 条，减少“硬编结论”和“空数据当 0”；最后做第 5-8 条的成本、反方与评测优化。
