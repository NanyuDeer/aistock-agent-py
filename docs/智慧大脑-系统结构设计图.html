现状结构：每个功能一条竖井，靠页面和数据库间接耦合

前端每张卡各自调接口拼结论；app-api 每个模块各抓各的数据；agent-py 由 supervisor 一次路由到单个 Agent，执行完即 END。

前端 / Agent → 接口调用 supervisor 图内路由 重复取数 / 割裂 / 人工断点 读写存储 编号割裂点，可点击

目标结构（能力全景）：7 条纵向泳道 + 底部共享账本，研究层保留 8 个能力域

这张图回答「系统有哪些能力」：触发 → 感知 → 研究 → 研判 → 校准 → 表达 → 出口，底部是全图共享的记忆与治理脊柱。8 个研究能力域各是一个可独立编译、单测、回放的 LangGraph 子图，点击带 ⊞ 的节点展开。运行时并不 8 个并列全跑——执行形态见「③ 执行：规则层 + 研究层」：R5 是唯一 lead agent，R2/R3/R4/R7/R8 收敛为它按需调用的子 agent，R1/R6 收敛为确定性计算工具。

LangChain 工具调用 证据 / 论点写入与投影 研判与落账 互相影响 / 校准回灌 渲染 / 只读

执行结构：规则层管「怎么跑」，研究层管「怎么想」

规则层是确定性骨架：触发、档位模板 G1、工具权限 G2、账本、裁决、校准、渲染。研究层是智能 agent：R5 归因主控是唯一 lead agent，在规则层给的 RunBrief 边界内决定「先查谁、查几次、够不够」；R2/R3/R4/R7/R8 是它按需调用的子 agent，各自独立上下文、独立工具子集、独立步数上限，只返回结构化 claim；R1/R6 是确定性计算，不是 agent。两层只通过 RunBrief / ResearchResult 两个结构交互，研究层不直接写账本。

规则层 · 确定性 研究层 · agent RunBrief / 按需调用 ResearchResult / 证据 研判与落账
CHANGE 01

入口：从「意图分类器」到「运行编排器」

现在supervisor 把请求分给 11 个 Agent 之一，执行完直接 END；一次 run 只走一条分支。
目标run_orchestrator 按触发源 + 标的 + 预算选择运行档位，并行扇出多个研究子图，全图共享一份 state。

意图分类仍然保留，但只用于选择档位，不再决定「只跑谁」。

CHANGE 02

状态：从「各自 END」到「一份增量证据账本」

现在Agent 各写各的报告文本；AgentState 名义共享，实际每个 Agent 跑完就结束，跨 Agent 无中间结论。
目标append-only channels：evidence / claims / conflicts 按 id 归并；节点只写增量，下游按 subject / sector / 时间取投影。

不是让所有节点读全量上下文，而是读「与自己相关的切片 + 增量」，token 成本可控。

CHANGE 03

数据：从「模块各抓各的」到「API 工具化 + 统一 provenance」

现在quote / monitor / fear-greed / stock-trace 各自直连腾讯、同花顺、Tushare，缓存与口径不一致。
目标app-api 仍是数据 owner；每个能力包成 StructuredTool，统一返回 provenance / quality / error，全图共用。

Agent 不再直连外部数据源；工具失败必须显式 failed，不允许空数组静默归零。

CHANGE 04

研究：从「单 Agent 拍结论」到「研究子图互相取用」

现在趋势、风口、事件、洞见各是一个 Agent，各用各的工具与提示词，互相不知道对方看到了什么。
目标每个功能变成研究子图：读共享证据，暴露只读工具；事件热度进风口，市场基调与板块强度进个股归因，个股龙头再反哺板块。

功能负责人仍然维护自己的子图，但输入输出统一走证据 / 论点契约。

CHANGE 05

研判：从「多份报告」到「一个 judgment_id」

现在晨报、个股洞见、播报、对话各自生成结论；同一只票在不同页面可能口径不同。
目标多方 / 反方 / 冲突消解 / 研判落账四个节点产出唯一研判；所有出口引用同一个 judgment_id。

高置信必须至少两个独立来源一致；反方与失效条件不可省略。

CHANGE 06

校准：从「复盘文件 + 人工」到「自动验证 + 方法回灌」

现在review → snapshot → iterate 产物是文件，人工看完改提示词，改动与研判效果无法对应。
目标verifier 到期回填实际走势，method_evolver 把失败模式转成方法版本，反馈给研究子图作为先验。

复盘不再是一次性文档，而是图里的反馈边；每次改动都可追溯到版本与样本。

CHANGE 07

事件：从「三套库」到「一个事件主记录」

现在agent event_store、app-api event_entities、calendar events 平行存在，实体链接与存活度口径不一致。
目标event_perception 统一抓取与去重，生成事件主记录 + 实体链接证据；其他节点只引用 evidence_id。

事件结论反哺风口热度，风口强度又影响个股归因，形成真正的跨功能传导。

CHANGE 08

出口：从「前端拼结论」到「前端只渲染」

现在首页、个股页、板块页、选股页各自调 3-6 个接口，在组件里拼成结论；对话与页面各说各话。
目标页面只消费 judgment / evidence 投影；卡片降级为证据附件；对话只读账本，新结论必须回写。

播报可以扩写叙述，但不得引入研判之外的新结论。

CHANGE 09

洞见卡片：从「个股单打」到「市场→板块→个股」

现在前端只调 /api/cn/favorites/movements 一个接口；卡片主因由这只票自己的行情、新闻、公告归因，大盘与板块强弱不参与结论。
目标前端接口不变，后端改成同一张图：市场定基调 → 板块给强弱 / 龙头 → 个股判「板块共振 / 逆板块 / 个体事件」，结论带三层证据与冲突标记。

板块强、个股只是跟涨时，卡片会写「板块带动」而不是硬编一个个股利好；龙头异动对板块强度的修正进入下一轮，不在同一 run 内成环。

CHANGE 10

大盘溯源：从「复盘 worker 单独成稿」到「同一账本的复盘视图」

现在复盘 Agent 自己抓数、自己归因、自己写 schema 2.0 的 market_trace；大盘溯源页只读这一份报告，和早报、个股、板块的结论不共享证据。
目标复盘是同一张图的 review 视图：主因 / 备选 / 被否 / 风险 / 次日验证都引用 M1 evidence 与 M2 claim，结论落 M3；页面只渲染，不再二次归因。

同一天的大盘结论只存在一份，早报、收盘复盘、大盘溯源口径一致；次日验证由 C2 回填，而不是人工对照。

CHANGE 11

边契约修正：按依赖方向与同 run 可执行性消除不自洽

原则不按原图“画了什么”保留，按数据依赖、执行顺序与是否成环重新连线；反向修正一律放到下一轮。

① 工具带补齐 P3/P4/R1/R5/C2/E1/E3/E4；② 板块→趋势改为 R2→R1（wind 先执行）；③ 补 R1→R5（洞见读趋势）；④ R6 改读 M3 最近一条研判，避免 R6→J4→R6 成环；⑤ M4 先验下发 R1-R6，并补 M4→C1/C3；⑥ M5 补 P2/P3/R3；⑦ 补 E4→M3 回写、M3→J4 上一条研判；⑧ 补 P2→P3 事件主记录；⑨ T2/T4 触发边带 event_id/judgment_id。

CHANGE 12

研究层补齐 R7/R8，工具带改为三层权限

为什么R5 既做归因又做资金，职责过宽；宏观数据塞在事件研究里，市场级判断缺少「环境松紧」。

R7 资金/筹码研究员：资金流、龙虎榜、席位、两融、北向、大单 → 资金筹码 claim。R8 宏观/政策研究员：利率、CPI/PPI/PMI、汇率、政策文件、宏观日历 → 宏观政策 claim。两者都在研究层，产出进 M2，供 R2 板块、R5 归因、R6 仓位借用。

三层工具箱：公共箱（行情/K线/新闻/日历/恐贪/搜索）所有研究员可用；角色箱默认只给本职；跨箱需在作业书写「借用条」，运行时记 trace；写账本/用户数据/推送属敏感箱，需显式授权。

CHANGE 13

大盘溯源：从「一个老法师写报告」到「八个研究员 + 有边界 ReAct」

改前review 单次 deep_think：自己冻结快照、自己归因、自己写 schema 2.0，和早报/个股不共享证据。
改后T1 定时 → O1 选 review 档位 → P1/P2/P3 供证据 → R1-R8 供 claims → R5 列候选原因并用 ReAct 逐条验伪 → J1/J2 辩论 → J3 裁决 → J4 定稿落 M3 → E1 渲染大盘溯源视图；C2 三天后自动对答案。

共同点：触发时间、页面结构（现象/主因/备选/被否/次日验证）、due+3 预判都保留。区别：数据从私有快照变共享 M1，结论从报告文本变 judgment，失败允许写「证据不足」而不是逼模型编主因。

CHANGE 14

执行拓扑收敛：从「8 个研究员流水线」到「规则层 + 研究层」

为什么节点多不等于智能。8 个研究员固定顺序全跑，没人判断「要不要查、查到什么程度算够」，本质是流水线；R5 是唯一需要「多假设 + 反复验伪」的 agent，R1/R6 是纯计算，R2/R3/R4/R7/R8 是专项取证。
规则层触发、O1 编排、G1 档位模板、G2 工具权限、M1-M6 账本、J3 裁决、C1/C2 校准、E1-E5 渲染。全部确定性，规定「什么时候跑、必查什么、花多少预算、失败怎么降级」。
研究层R5 归因主控是唯一 lead agent；R2/R3/R4/R7/R8 收敛为它按需调用的子 agent，各自独立上下文、独立工具子集、独立步数上限，只返回结构化 claim；R1/R6 收敛为确定性计算工具。判断权集中到唯一该有判断权的地方。

两层只通过 RunBrief（必查清单 / 预算 / 超时 / 输出 schema）和 ResearchResult（claims / evidence_ids / partial / tool_calls）交互，研究层不直接写账本。每档 2 个必查 probe 保底，其余由 R5 按证据加查：既不会该查没查，也不会像流水线那样全跑。

CHANGE 15

V2.1：补上自检、学习、快慢档与风险非对称

为什么V2 能取证但不会自检、不会把教训变成下次的先验；黑天鹅和普通波动同权；所有任务都走完整慢思考，盘中信号来不及。
新增 C4 元认知R5 出结果后独立检查三件事：结论有没有对应证据、有没有互相矛盾的证据、关键证据失效时结论会不会翻转。不通过打回一次或降置信 0.15。
新增 C5 离线反思非交易时段读 M3/C2/M4，修正错误归因、把反复验证的模式蒸馏成 M4 语义条目（需 ≥3 个支撑案例）、生成待验证假设。只写 M4，不改 M3 历史结论。
强化四处G1 加 fast / slow / escalate 快慢档（规则信号只提示不出口结论）；J2 强制等强度反证；J3 风险事件 bear 权重 ×1.5、置信上限 0.5；M3/M4 检索改三因子（relevance / recency / hit_rate），只排序不删除。

没加：RL 微调小模型（样本少、成本高）、删除式遗忘（账本是审计事实源）、七个脑区各建模块（会把刚收敛的图重新变臃肿）。依据：FrugalGPT 级联、Anthropic agent memory dreaming、Generative Agents 检索、TradingAgents 风控团队。

落地顺序：组长先行，一条真实链路先跑通，其余模块按规范接入

  1. 第一阶段（样板链）：数据平台 → 洞见 → 播报 → 市场。产出 evidence / claim / judgment 三张契约、3 个研究子图、1 个播报出口，先证明「互相影响」确实提升结论质量。
  2. 第二阶段（横向接入）：趋势、风口、事件、业绩、节奏按同一契约迁移；每个模块只需暴露工具 + 写证据 / 论点，不改前端。
  3. 第三阶段（出口切换）：首页、个股页、事件页切到 judgment 渲染；旧接口保留只读兜底，观察两周再下线。
不变量 1：app-api 是唯一数据源 不变量 2：一个 judgment_id 只落一次账 不变量 3：前端不拼结论 不变量 4：无来源不进入高置信
