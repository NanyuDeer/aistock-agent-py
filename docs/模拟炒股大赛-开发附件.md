# ① 口径定义表

> **这张表是"所有收益率切到同一引擎"的落地前提。** 每个指标只允许一个定义、一个来源；改口径必须 bump 版本号并可回算。
> 技术实现可以是 `js` 后端函数或共享库，但**公式只有这一份**。

## 1.1 基础量与记号

| 记号 | 含义 | 取值 / 来源 |
| --- | --- | --- |
| `INIT` | 初始虚拟资金 | **300,000.00**（常量，唯一来源） |
| `NAV(t)` | 第 t 个交易日收盘后的净资产 | `现金 + Σ(持仓数量 × 该日结算价)` |
| `P(t)` | 该日结算价 | 见 1.3 结算价格口径 |
| `BENCH_SAME(t)` | 同池等权基准 | 开局日把推荐池全部标的等权买入并持有到 t |
| `BENCH_MKT(t)` | 大盘基准 | 沪深 300 同区间收益 |

## 1.2 指标定义（唯一来源）

| # | 指标 | 公式 | 分母/边界处理 | 展示位 |
| --- | --- | --- | --- | --- |
| M1 | **累计收益率** | `NAV(t) / INIT - 1` | 初始为 0 | 持仓页、战报、榜单 |
| M2 | **日收益率** | `NAV(t) / NAV(t-1) - 1` | 首个交易日以 `INIT` 为基 | 战报逐日曲线 |
| M3 | **超额收益（同池）** | `M1 - BENCH_SAME(t)` | — | 战报 |
| M4 | **超额收益（大盘）** | `M1 - BENCH_MKT(t)` | — | 战报（次要） |
| M5 | **最大回撤** | `max_t [ (peak_NAV - NAV(t)) / peak_NAV ]` | `peak_NAV` 取历史最高；`peak_NAV = 0` 时为 0 | 战报、榜单 |
| M6 | **胜率** | `盈利平仓笔数 / 总平仓笔数` | **只统计已平仓**；无平仓显示"—" | 战报、榜单 |
| M7 | **持仓天数（均值）** | `Σ(卖出日 - 买入日) / 平仓笔数` | 无平仓显示"—" | 战报 |
| M8 | **功能贡献度** | 见 1.4 | 见 1.4 | 战报核心模块 |

## 1.3 结算价格口径

| 项 | 规则 |
| --- | --- |
| 日结算价 | 该交易日**收盘价**（不复权，与行情源一致） |
| 盘中估值 | 最新可成交价（用于"盘中估值"展示，**不写入结算**） |
| 停牌标的 | 用**最近一个有效交易日收盘价**，并标记 `stale=true`，不参与当日排行变化计算 |
| 缺数据的交易日 | 该标的该日标记**未结算并顺延**，禁止写入推测值 |
| 成交价 | 下单时刻**最新可成交价**（涨跌停时不可成交） |

## 1.4 功能贡献度（M8）—— 重点

**问题**：战报里说"66% 的收益来自 AI 帮我选"，这个 66% 必须有算法，否则整个反哺立论站不住。

**数据前提**：每笔买入必须带 `source_feature`（依据的功能，如 `ai_pick` / `rhythm` / `news` / `event`）与 `source_ref`（推荐批次或动态卡片 id）。用户自主下单记为 `self`。

**计算步骤**

1. 对每笔**买入**，计算其标的从买入到（卖出日或局末）的盈亏 `pnl_i`（已实现 + 浮动）
2. 按 `source_feature` 汇总：`PNL(f) = Σ pnl_i`（i 属于该功能）
3. 设 `PNL_ALL = Σ pnl_i`（全部成交）
4. **贡献度**：
   - 若 `|PNL_ALL| ≥ max(1000, INIT × 0.2%)`：`CONTRIB(f) = PNL(f) / PNL_ALL`（可为负）
   - 若分母过小：**不展示百分比**，只展示 `PNL(f)` 绝对值，并提示"本局盈亏接近 0，占比无意义"

**展示规则**

- 战报里给出**前 3 个功能**的贡献度 + 其余合并为"其他"
- **必须同时显示样本量**：`基于 N 笔成交`
- **必须带免责**：`样本很小，仅供参考`（N < 5 时强制显示）

> ⚠️ 这是整套反哺最重要的一个数字，也是最容易被质疑的一个。**宁可标注"样本不足"，也不要给一个看起来很精确的假百分比。**

## 1.5 版本与回算

| 规则 | 说明 |
| --- | --- |
| 版本号 | 任一公式或常量变更 → `methodology_version` +1 |
| 落库 | 每次结算记录当时使用的 `methodology_version` |
| 回算 | 支持按指定版本重算历史局，用于对比 |
| 禁止 | 多处内联常量（`INIT`、基准、阈值） |

## 2.3.1 T3.5 · 口径修正 8 条（已定）

> 这 8 条来自 PRD 技术附录 F.7。其中 5 条会改变选股结果，**必须在配置外化框架就绪后一起改**，并跑一次「旧口径 vs 新口径」对比。

| # | 改什么 | 前 → 后 | 验收标准 |
| --- | --- | --- | --- |
| 1 | 趋势预筛成交额单位 | `MIN_AVG_AMOUNT` 800000 → **80000**；`AVG_AMOUNT_THRESHOLD` 500000 → **50000**（并标注单位「千元」） | 同一交易日趋势候选数量增加，且新增标的日均成交额落在 8000 万~8 亿之间 |
| 2 | AI 帮我选的 rank 归属 | LLM 只决定入选与理由；**rank 由代码按 `weight` 降序赋值** | 同一批次重排前后：**集合不变、仅顺序变**；且顺序与 `weight` 降序完全一致 |
| 3 | 机构来源窗口 | `NOW() - INTERVAL '3 days'` → `resolveTradingDaysStart(3, now)` 生成的交易日窗口 | 跨周末场景（周五→周一）候选数不再骤降；与机构列表接口同窗口结果一致 |
| 4 | `min_resonance` 范围 | 控制器与 `internal.ts` 的 `[2,4]` → **`[2,3]`** | 传 4 返回参数错误；传 2/3 结果与历史查询一致 |
| 5 | 盈利预测 | ① 净利润支持「亿元/万元」换算；EPS 同比支持「下降」取负 ② 预测四榜加 `institutionCount >= 3` ② 中期改逐机构聚合 | 抽取 20 只样本，`null` 率显著下降；机构数 <3 的标的不再进入预测榜 |
| 6 | 趋势评分的 LLM 注入 | 模块级 `aiScores` → `calculateTrendScore(symbol, opts)` 显式入参；批量固定不传 | 同一份数据重复跑 3 次，`score` 完全一致 |
| 7 | 复权口径 | 指标与 `ma60` 剔除改用**前复权**收盘价 | 挑近一年有除权的标的，新旧 `score` 差异可解释；60 日线判定与页面 K 线视觉一致 |
| 8 | 配置快照 | `ai_stock_selection_runs` 加 `config_snapshot JSONB` | 每次 run 都能从快照还原出权重/阈值/窗口/prompt 版本；用快照可复算出同样的结果 |

**交付物**：
1. 代码改动 + 单测
2. **新旧口径对比报告**（同一交易日，候选数量 / Top10 集合差异 / 分值分布）
3. 若发现某条改动导致候选池异常（例如数量暴增），需回退并上报

## 3.3 三条硬要求

1. **`card_impression.position` 必须有**。没有位次，就无法把"卡 1 被点得多"和"这个功能有用"区分开——这是曝光偏差的唯一解法。
2. **`order_submit.source_feature` 必须与卡片/推荐理由同源**。否则功能贡献度算不出来。
3. **埋点事件名与参数只允许来自本表**，新增须先改本表。

## 4.1 被问到时的三个标准回答

**Q：用户凭什么玩？**
A：5 天、点一下开始、买什么不用自己想；局末有战报和排名，能分享。门槛低到"顺手"。

**Q：这会不会变成荐股？**
A：全程虚拟、无真实资金、不承诺收益；榜单只排虚拟收益；用户提交的流派需经审核且禁止收益承诺。**合规细则待法务确认。**

**Q：怎么证明有用？**
A：三条：① 每条操作都能追到"依据哪个功能"；② 每张卡记曝光位次，剔除位置偏差；③ 用功能贡献度而非点击率。**样本量是最大限制，会如实标注。**
