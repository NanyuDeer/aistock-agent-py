概览

要解决的问题

模拟炒股本身是反人性的：没有真实盈亏，却要用户花时间看盘、分析、下单，大多数人坚持不了几天。因此"缩小版实盘"这条路走不通。

同时 App 存在一个结构性缺口："看市场"一侧已经相当完整（晨报 / 午报 / 晚报、风口 / 消息 / 事件 / 恐贪 / 节奏、复盘归因、预测验证），"看自己"一侧完全空白——持仓陪伴 / 交易复盘 / 动态估值三个页面是空壳，全 App 没有任何下单、持仓、收益记录能力。

另一件事：系统里已上线的大量 AI 能力只给结论、从不被验证；目前只有"预判环"与"节奏分支验证"具备可验证结果。

产品决策

把它定位为「AI 陪跑的策略竞技场」：用户开一局即拿到「AI 帮我选」给出的 Top10 推荐池，虚拟买卖、可全程放手给 AI，平台用统一内核记账，产出战绩海报与功能贡献度，局内分榜竞技。

一句话：模拟盘只是外壳，核心是游戏化地验证产品功能。

v0.3 · 14 项决策已定 · 2026-10-15。本文档描述 App「选股」主 Tab，与上方「模拟炒股大赛 PRD」是两个不同的功能。

0. 边界声明

本文档只描述「选股」主 Tab 及其四个子 Tab。它不属于模拟炒股大赛——大赛只是它的消费方（见第 8 节）。另外本文档只做「选股口径」，不做「交易策略」。

术语约定：全文用「流派」指代选股口径。会上出现过的「交易风格」与同事提到的「交易流派」，在本语境下同义。

1. 概念定义：流派是选股口径，不是交易策略

选股口径（流派）交易策略
回答的问题买什么怎么买
典型内容价值 / 成长 / 动量 / 事件驱动 / 机构跟风 / 趋势仓位几成、持有多久、止盈止损、分批或网格
本功能归属✅ 本文档范围❌ 不属于

为什么不做交易策略

  1. 保持低门槛：让用户预设交易策略，等于把研究成本重新加回来，与"零成本拿到推荐"的定位冲突。
  2. 保持归因清晰：若用户自定义交易策略，收益该归功于"AI 选股"还是"用户的策略"就说不清——而这恰是大赛要反哺的核心命题。
  3. 与大赛口径一致：大赛的选股来源统一来自本功能，不掺入用户自定义策略。

流派的正确作用范围：效力止于"池子里有哪些票"，不约束用户的买卖动作。

顺序上还有一条规矩：若将来要做"交易策略"，正确次序是先跑大量数据 → 从行为里观察出打法 → 再推荐给同类用户，而不是先让用户选打法。观察在前，推荐在后。

3. 决策前提：现有四个子 Tab 就是流派 已定

这是一条已确认的前提，它把本需求从"新增"变成了"重构 + 完善 + 扩展"。

也就是说：我们不是要发明"流派"，而是要给已经存在的四个流派补上一个统一的流派层。由此必须做两件事：① 把四个硬编码子 Tab 抽成流派注册表（否则 DIY 与扩展无从谈起）；② 决定是否要在数据层把这四条异构链路收敛。

3.1 收敛路径 已定：渐进

路径做法代价结论
A 薄封装保留四套异构数据源，流派只做一层注册表（声明数据来源、口径说明、产出字段、刷新策略）低成本、快上线；流派能力受限于已有信号本期起点
B 统一引擎收敛成同一套「候选池 → 多维打分 → 选出 TopN」引擎，每个流派只是一组筛选条件与权重高成本；但它才是 DIY 真正的天花板中期目标
渐进A 起步，逐步把能收敛的维度收进统一引擎兼顾✅ 已定

3.2 为什么"渐进"可行——一个现成的落点

「AI帮我选」的候选池已经携带多维信号：trend / institution / forecast / market / technical / capitalFlow / events / riskFlags。但当前是硬编码权重——按名次线性给分（TOP_PER_SOURCE + 1 - rank，TOP_PER_SOURCE = 10）、同行业最多 3 只，规则全部写死在代码中。

也就是说："流派可配置化"的落点其实已经存在——流派 = 对这些已有维度的一组筛选条件与权重。本期只需把这组硬编码参数外化为流派配置，就能让 DIY 在低成本下成立。

4. 核心模型

模型定义
流派注册表一条流派 = { id, 名称, 一句话说明, 数据来源, 口径定义, 产出字段, 刷新策略, 状态, 口径版本 }。四份硬编码子 Tab 收敛于此
流派配置（口径）该流派在已有信号维度上的筛选条件与权重（例：在 trend 维度取前 N、institution 维度加权 W）
用户流派档案用户当前选中的流派 + 变更历史 + 自我描述（DIY 提交内容）
DIY 提交单用户提交的流派：文本描述 + 可映射性判定 + 人工复核结论 + 最终归属
反馈记录一次推荐结果的满意度 + 原因标签 + 关联批次
推荐批次一次 Top10 生成结果（ai_stock_selection_runs），是反馈与画像的挂载点

状态流转

流派： 草稿 → 待审核 → 已上架（口径版本 +1，历史需回算）→ 已下线（不可删除） DIY 提交单： 已提交 → agent 初审中 → 待人工复核 → 已上架 / 已归入默认 → 已通知用户

5. 功能需求

FR-01 流派注册表与选择

目的：让流派从"前端硬编码"变为"可配置、可扩展"，同时让用户用最低成本表达自己想要哪种选法。

  • 四个现有子 Tab 收敛为流派注册表，前端不再硬编码条目 已定
  • 流派以一行胶囊按钮呈现，沿用现有子 Tab 条的视觉规范（见 2.2），不重新发明交互 已定
  • 首次引导：胶囊 + 首次引导，两者都做 已定（详见 5.1）
  • 默认流派：跳过引导或未建档时，默认停在「AI 帮我选」 已定
  • 记住用户选择：选择落库，下次进入沿用（现状不记忆）已定
  • 流派只影响选股口径，不限制用户的买卖动作 已定

5.1 首次引导（按 #4 新增）

项规格
触发条件用户尚无流派档案时，首次进入「选股」主 Tab
频次只出现一次；出现后即写入档案（无论是否选择）
形态底部弹层 / 引导卡，列出四个流派 + 一句话说明（复用注册表里的「说明」字段）
是否必须选可跳过。跳过则落默认「AI 帮我选」，档案标记为 skipped
生效时机选完立即生效并记住，不需要二次确认
后续进入不再弹引导，直接落在上次选中的流派
设计意图：一次性把"这里有几种选法"讲清楚，避免用户永远只用第一个 Tab；同时用"可跳过"保证零门槛路径不被阻塞。

FR-02 流派内容展示

  • 每个流派需在注册表中声明自己的产出字段与展示形态（异构是现状，本期不强行统一）
  • 结果页需能回答"这批票是按什么口径筛出来的"——每只标的标注所属流派
  • 结果一旦生成即固化，不因后续口径变更而改写（供大赛等消费方锁定使用）
  • 修正现状缺陷：「AI帮我选」的展示排序应与后端 rank 一致，不再按当日涨跌幅重排 已定

FR-03 满意度反馈（可归因）已定：做，且必须可归因

目的：把"情绪"变成"可执行的修改项"，并为口径迭代提供证据。

  • 粒度：P0 做"整组推荐"粒度；单只标的粒度放 P1 已定
  • 满意：轻量，不追问
  • 不满意：必选一个原因，四个选项 已定：标的不好 / 推荐理由不成立 / 时机不对 / 这类票我不想要
  • 全部记录 user_id + 流派 + 推荐批次 + 时间
为什么必须可归因：只有一条"不满意"，系统不知道该改什么。原因分布本身就是"口径该往哪调"的证据——例如 70% 选「推荐理由不成立」，该改的是理由生成，而不是选股逻辑。

FR-04 DIY 提交流派

目的：让用户的方法论进得来，同时采集用户画像。

提交内容：流派名称 · 怎么选股（自由文本，必填） · 可选举例说明

关键机制：可映射性判定 已定：agent 初审输出 + 人工复核确认。DIY 能不能低成本上架，取决于用户的描述能否落到已有的信号维度上。因此 agent 初审必须输出这个判定，而不是只判断"像不像已有流派"。
判定结果含义处理
可映射描述能落到已有维度（trend / institution / forecast / capitalFlow / events / market / technical / riskFlags）的组合上可上架——本质是生成一组新的筛选条件与权重，无需新数据源
不可映射需要当前不存在的数据源或口径标记「需开发」，不进本期上架队列，仅作为需求线索沉淀

处理链路

用户提交 ↓ agent 初审：① 能否归入已有流派？ ② 若不能，能否映射到已有信号维度？ ├─ 可归入 → 直接归入该流派 + 保留用户自我描述（画像数据到手） ├─ 可映射 → 输出「映射到哪些维度 + 大致筛选/加权方式」→ 待人工复核 └─ 不可映射 → 输出缺口说明（缺什么数据源）→ 标记「需开发」 ↓ 后台人工复核（本期做最小形态：待审列表 + 通过/驳回 + 归类）【已定】 ├─ 通过 → 上架为新流派（口径版本 +1，需回算）；决策权：产品/组长 1 人拍板【已定】 └─ 不通过 → 归入最接近的默认流派，并告知用户 ↓ 通知用户结果
#约束理由
1agent 初审必须输出可映射性判定与映射方式否则人工复核没有依据，只能重读一遍用户的话
2上架 = 口径变更，必须走版本号 + 历史回算，不可直接生效否则历史结果与往后结果不可比
3已上架流派不可删除，只能下线否则历史数据无法解释
4提交需有频次限制与重复检测防滥用、防与现有流派高度重复
5用户描述中不得出现收益承诺类表述合规
6审核结果必须通知用户否则用户不会再提交第二次

8. 与模拟炒股大赛的关系

大赛是消费方，本功能是提供方。大赛只从本功能取三样东西（见大赛 PRD 的 FR-12）：

  1. 一份按指定流派的、可锁定的 Top10（开局取一次，局内不变）
  2. 稳定的标的标识（可按同一标识回溯到推荐批次）
  3. 推荐理由文本（用于大赛战报里的"本笔依据"）
大赛的开局规则是：按用户当前流派取该流派的 Top10，并连同批次一起锁定，局内不可切换。因此同榜选手的池子一致（同一批次 + 同一流派），跨流派的可比性由"按流派分榜"解决。

9. 风险与缺口

#风险说明建议
1后台审核系统不存在现状无任何选股相关审核/配置后台，同仓库也无后台前端。DIY 的"人工复核"要从零建本期只做最小形态：待审列表 + 通过/驳回 + 归类

4样本量反馈与采纳率在早期用户量小，结论不显著反馈先作为定性线索，不做自动调权（本期不做）
5口径频繁变更导致历史不可比DIY 上架会不断新增流派强制版本号 + 回算（FR-05）
