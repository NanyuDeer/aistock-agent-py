# 洞见 App 使用体验报告 —— 完整交易日全流程模拟

> **报告目的**：以一个普通股民「从盘前起床到盘后睡觉」的真实一天为主线，逐场景模拟其使用 App 的动作，核对 App 前端**有没有解决方案**、**哪里用得不顺（体感）**、**哪里不够准确（正确性/时效）**，并给出分级结论与整改建议。
>
> **评估范围**：**仅前端（`aistock-app-frontend`）** 的页面、交互与数据时效；后端能力只作为参照，不做后端实现评估。
>
> **方法**：静态代码走查（页面 / 组件 / API / 交易时间工具），关键结论附 `文件:行号` 证据。未运行真机，故「接口是否真的返回数据」不在本报告结论范围内。
>
> **时间线**：一个正常交易日（周一~周五、非节假日）。盘前 08:00–09:15 → 集合竞价 09:15–09:25 → 早盘 09:30–11:30 → 午间 11:30–13:00 → 午后 13:00–15:00（含尾盘 14:30–15:00）→ 盘后 15:00 起 → 夜间 20:30 后。
>
> **生成日期**：2026-10-11

---

## 0. 一句话结论

洞见 App 是一个「**盘前读懂 + 盘中盯自选 + 盘后复盘 + 随时提问**」的**辅助决策工具**，**不是交易终端**（全 App 无下单/成交/持仓录入）。它的「看市场」一侧在盘前和盘后做得相当完整（晨报/午间报/晚报、风口/消息/事件/恐贪/节奏、复盘归因、预测验证），盘中「盯自选」也已可用（多入口 60s 准实时刷新 + App 端异动 WebSocket）。

**当前最影响信任的是：「AI 帮我选」是写死假数据却没有任何"演示"标识，且是选股 Tab 的默认入口；最影响盘中可用性的是：个股详情页没有分时图、没有盘口五档；最让人"点击即失望"的是：持仓陪伴/交易复盘/动态估值三个页面是空占位却可被导航点开。**

---

## 1. 走查前提：这个 App 是什么 / 不是什么

**信息架构（前端）**

- 底部 **3 个 Tab**：早点听 / 选股 / 提醒（`src/shared/components/MainTabs.vue:87-94`），内容分别为 `MorningContent / StockContent / AlertContent`。
- 底部**另有一条常驻全局对话栏**：`报告 | AI 对话胶囊 | 自选`（`src/shared/components/GlobalChatBar.vue`）。
- **没有任何下单/成交/持仓录入能力**——「持仓陪伴 / 交易复盘 / 动态估值」三个页面是空占位（见 §4 P0-4）。

**由此定调**：所有「交易」场景，App 的定位都是**信息与解读**，而非执行。走查按"辅助决策工具"评估——不苛求它去做下单，但应确保「信息足够准、足够新、足够顺」。

## 2. 全天时间轴走查

每节结构：**用户此刻想干什么 → App 现有方案（含证据）→ 判定 ✅/🟡/🔴 与问题**。

### 2.1 盘前 08:00–09:15 —— 覆盖最完整的时段 ✅

用户场景：起床想快速了解「今天该关注什么」。

| 用户需求 | App 现有方案 | 证据 | 判定 |
|---|---|---|---|
| 今天大盘/情绪怎么样 | 恐贪指数（首页 Tab 头右侧按钮） | `MainTabs.vue:25` | ✅ |
| 今天有什么大事/风口 | 晨报 + 风口洞见 + 消息洞见 + 重磅事件跟踪 + 节奏洞见 | `MorningContent.vue:92,111,135,159` | ✅ |
| 未来几天有哪些事件 | 未来事件时间线 | `chat/pages/event/timeline.vue` | ✅ |
| 帮我选几只股 | 选股 Tab（AI 帮我选/趋势股/机构热门股/业绩预测） | `StockContent.vue:32` | 🟡 见下 |
| 听一遍晨报 | 晨报支持音频（音频条可选渲染） | `briefing/index.vue` | ✅ |

**判定：✅ 盘前覆盖完整，是 App 最强时段。**

**遗留问题**
- 🔴 **「AI 帮我选」是硬编码假数据，且无演示标识**（P0-1）：`AiPickContent.vue:18-24` 写死 5 只股票（精达股份/裕同科技/中国卫星/中国中车/卫星化学），代码注释虽写明"一期为模拟数据"，但**界面上没有任何"演示数据"角标**；且它是选股 Tab 的**默认第一个子 Tab**（`StockContent.vue:32` 中 `{ key: 'ai', label: 'AI帮我选' }` 排首位，`StockContent.vue:16` 默认 `v-show` 的初始态即 AI）。用户第一眼就会把这 5 只写死的推荐当成「AI 实时真实选股」——**直接损害产品可信度**。

### 2.2 集合竞价 09:15–09:25 —— 整段缺失 🔴

用户场景：竞价是 A 股短线用户最关注的 10 分钟，想第一时间看「哪些自选股高开/低开、竞价强弱」。

**App 现有方案：无任何竞价专属内容。**

- 前端**有**判定函数 `isCallAuction()`（09:15–09:25）与 `getMarketStatus()`（返回「集合竞价」文案），见 `src/shared/utils/tradingTime.ts:85-102`。
- 但 `getMarketStatus` 只被用作**一句状态文案**（自选异动页顶部"市场状态"、市场 store），`isCallAuction` 仅被 `getMarketStatus` 内部调用——**没有任何页面渲染"竞价"专属内容**（无竞价异动、无竞价高开/低开榜、无自选股竞价表现）。
- 首页/自选列表此刻也不会提示"正在集合竞价"。

**判定：🔴 缺失（P1-6）。** 这是 A 股短线用户最关心的 10 分钟，App 在这一段是"内容真空"。

### 2.3 早盘 09:30–11:30 —— 盯自选可用，看个股偏弱 🟡

用户场景：开盘后想盯自选股涨跌、看某只票的分时与买卖盘口、盯异动。

| 用户需求 | App 现有方案 | 证据 | 判定 |
|---|---|---|---|
| 自选股涨跌幅自动刷新 | 交易时段内每 60s 原地刷新行情（默认视图即可） | `favorites/pages/favorites.vue`（`syncQuoteRefresh`） | ✅ |
| 自选股盘中分时走势 | **需手动开启分时模式**（表头"三横线"），开启后 60s 轮询分时 | `favorites.vue:291-299,341-351` | 🟡 多一步 |
| 单只个股实时行情 | 个股详情页 60s 轮询（最新价/涨跌/量比/换手/涨跌停价…） | `favorites/pages/detail.vue:2125-2142` | ✅ |
| **看个股分时图** | **详情页无分时**：K 线周期仅 `daily/weekly/monthly`（`detail.vue:919` 类型定义），视图切换为「短线(日/周)/长线(年)」（`detail.vue:948-950`），**无分钟/分时** | `detail.vue:919,948-950` | 🔴 缺口 |
| **看盘口/五档** | **无盘口五档**，只有涨停/跌停/均价内联展示 | `detail.vue:48-52` | 🔴 缺口 |
| 盯异动 | App 端 WebSocket 实时；H5/小程序 60s 轮询 | `favorites/pages/monitor.vue` | ✅ |
| 让 AI 解读某股异动 | AI 异动解读页 SSE 流式，进页触发 + 当日缓存 | `useAlertSSE.ts:141,174-196` | ✅ |
| 盘中看板块/大盘强弱 | 风口龙头/板块详情/板块四环均**进页拉一次、无轮询**；板块四环明确"20:30 前主因未产出" | `leaders.vue:676-680`；`sector-loop.vue:65,389` | 🟡 盘中无当日数据 |

**判定：🟡 盘中"盯自选"已可用，但"看个股踩点"仍弱。**

**遗留问题**
- 🔴 **个股详情无分时主图、无盘口五档**（P1-2）：盘中想判断"这只票现在是拉升还是回落、买卖力量如何"，详情页给不出分时走势与五档盘口，只能退回自选列表看 MiniKLine。
- 🟡 **分时图仍需手动开启**：默认列表已自动刷新数字，但"看分时走势"仍要用户先切分时模式，多一步操作。
- 🟡 **09:30–12:00 首页仍是"晨报"语境**：`useBriefingCard.ts` 切换规则是「15:30 后→晚报、12:00–15:30→午间报、其余→晨报」，上午盘中首页没有"盘中"专属内容位。
- 🟡 自选页顶部"平均涨幅"为简单算术均值口径，未说明是否按仓位加权，易被误读为组合收益。

### 2.4 午间休市 11:30–13:00 —— App 独有亮点 ✅

用户场景：午休想吃个饭，快速回顾上午、看下午机会与风险。

**午间报**（`briefing/index.vue:35-130`；`shared/utils/middayReport.ts`）：summary + 分段结论 + 「机会/风险」双栏对位 + 风险提示，音频可选。**判定：✅ 满足，是 App 差异化亮点。**

**遗留问题**
- 🟡 午间报音频为**可选**（后端有才渲染音频条），无音频时只出文字——用户无法预期"是否有得听"。

### 2.5 午后 13:00–15:00（含尾盘 14:30–15:00）—— 与早盘同源，尾盘空档 🟡

- 与早盘同源缺口：个股详情 60s 轮询 + 自选列表 60s 轮询；**无盘口、无分时主图**（同 P1-2）。
- **尾盘（14:30–15:00）没有针对性功能**：无尾盘异动/尾盘资金/打板相关。`getTradingTimeSlot` 只有 pre/intraday/post 三档，无法区分尾盘。

**判定：🟡 与早盘同源缺口，尾盘为空档。**

### 2.6 盘后 15:00 起 —— "看市场"很完整，但"看自己"完全缺失 🟡

用户场景：收盘后想复盘大盘走势、验证预测、看自己的持仓与交易。

| 用户需求 | App 现有方案 | 证据 | 判定 |
|---|---|---|---|
| 今日市场复盘 | 晚报（`useBriefingCard.ts` 15:30 后切晚报）+ 大盘归因链 | `analytics/pages/traceability.vue` | ✅ |
| 板块强弱分析 | 板块四环/板块详情/风口龙头 | `sector-loop.vue` | ✅ |
| 验证此前的 AI 预测 | 预测验证页 | `analytics/pages/prediction-history.vue` | ✅ |
| 看财报/业绩报告 | 业绩报告/财报详情 | `reports.vue` | ✅ |
| 情绪节奏 | 节奏大师（盘前/午间/收盘三时点版本） | `rhythm/pages/index.vue` | ✅ |
| **我的持仓/交易复盘/估值** | **三个页面全是"页面开发中..."空占位，且路由与导航可达** | `pages-sub-app/portfolio/index.vue`、`review/index.vue`、`valuation/index.vue`；`pages.json:423,431,439` | 🔴 空壳 |

**判定：🟡 "看市场"完整，"看自己"全缺。**

**遗留问题**
- 🔴 **持仓陪伴 / 交易复盘 / 动态估值三个页面都是空壳**（P0-4）：点击即"页面开发中..."，盘后最刚需的"我的交易复盘/持仓"完全缺失。
- 🟡 市场洞见页有 **60s 前台常驻轮询**（`traceability.vue:255-262`）用于自动跨 15:30/20:30 切日，对耗电不友好。

### 2.7 夜间 20:30 后 / 非交易日 ✅/🟡

- 板块四环明确"收盘后数据更全（20:30 前主因未产出属正常）"（`sector-loop.vue:65`）；市场洞见 20:30 后落预判。**判定：✅ 有语义提示。**
- 非交易日降级：早点听**有**向前回退（最多 7 个自然日）并横幅标注（`briefing/index.vue:11-15,356,714-741`）——**✅**；其余模块基本**没有非交易日降级**（交易日判定已改以后端日历为准，但页面内容本身不做回退）。

## 5. 改进建议（按优先级）

### 5.1 优先（决定信任与盘中可用性）

1. **给「AI 帮我选」加显式占位标识**（P0-1）：最小改动在列表头加"演示数据 · 后续接入选股 Agent"；或在真实接口就绪前把默认子 Tab 改为「趋势股」（真数据）。
2. **个股详情补分时图**（P1-2）：K 线周期加"分时"，复用现有分钟链路（自选列表 MiniKLine 已在用）。
3. **盘口/五档**（P1-2）：如需支撑"看盘"，详情页增加五档买卖盘（依赖后端行情字段）。
4. **持仓陪伴 / 交易复盘 / 动态估值**（P0-4）：短期先**隐藏入口**（避免点击即"开发中"），或明确排期。

### 5.2 中等（盘中体验补强）

5. **集合竞价内容位**（P1-6）：盘前 09:15–09:25 在首页「今日专属」位置展示竞价状态与自选股竞价表现（复用 `isCallAuction/getMarketStatus`）。
6. **首页盘中语境**：09:30–12:00 增加"盘中"卡片（自选异动 + 大盘快照），避免全天只切晨报/午间报。
7. **尾盘场景**：14:30–15:00 的尾盘异动/资金（`getTradingTimeSlot` 目前无法区分尾盘，需扩展时段定义）。

### 5.3 细节

8. **底部双层导航**（P2-9）：评估是否把 `GlobalChatBar` 的「报告/自选」并入 Tab 或收纳，减轻底部拥挤。
9. **分时模式门槛**：考虑把"看分时"做成行内展开或自动分时，减少一次手动切换。
10. **自选平均涨幅口径**：在 UI 上标注统计口径（等权/是否含未开盘），避免误读为组合收益。
