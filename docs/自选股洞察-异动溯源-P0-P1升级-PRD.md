# 自选股洞察异动溯源 P0 / P1 升级 PRD

| 项目 | 内容 |
|---|---|
| 版本 | v1.0 评审稿 |
| 日期 | 2026-11-08，北京时间 |
| 用户 | 已登录并添加自选股的洞见用户 |
| 涉及端 | App、H5、Node API、Python Agent、行情与事件数据源 |
| 评估样本 | `mxfff` 自选股，2026-11-02 至 2026-11-06 可见的 12 张价格异动卡 |

## 1. 背景与目标

用户打开异动卡，需要知道股票发生了什么、有哪些可能的解释，以及每项解释有哪些证据。复盘发现，星帅尔报告曾用 15:05 的指数快照解释 14:49 的触发。晶华微报告引用了 08:45 发布的风险公告，但现有快照只能证明系统在 09:49 采集到了该记录。晶华微连续三天出卡时，用户也难以看出哪些信息是首次出现、哪些是旧事件延续。

- **P0** 确保触发归因使用合格的同期证据，并在列表、详情和报告中一致表达结论强度。
- **P1** 关联同一催化引发的连续异动，建立可重复的回放和周度评估。
- 本期范围为自选股价格异动的证据、归因和展示。异动检测阈值调整、全市场扫描、行情预测和投资建议另行立项。

## 2. P0 产品需求

### P0-1 固定每次修订的触发证据

1. 以 `event_id + trigger_revision` 定位一次归因，使用该修订的 `triggered_at` 作为截止点。首次触发时间、修订触发时间和窗口结束时间分别展示或保留。
2. 保存触发个股报价、涨跌幅基准及触发阈值。指数和板块报价记录供应商行情时间、系统采集时间及涨跌幅基准。同期指数默认采用触发时或之前最近一笔且距触发不超过 5 分钟的报价，5 分钟为首版配置。板块分时数据接入后采用同一时间口径，缺少可信时间戳时标记缺失。
3. 将证据区分为「触发时证据」「历史背景」「事后补充」。T-1 板块和资金数据用于历史背景。晚于触发的行情可在复盘中查看，并与触发归因分开展示。
4. 后续分析和重试读取指定修订的冻结快照。缺少同期报价时，结果明确提示数据缺失。

### P0-2 区分消息发布时间和首次可见时间

| 字段 | 定义 |
|---|---|
| 发布时间 | 来源发布公告或新闻的时间 |
| 系统首次可见时间 | 该条内容首次成功进入可供系统查询的数据源的时间 |
| 快照采集时间 | 归因流程将该条记录写入指定修订快照的时间 |

首次可见时间由上游入库流程写入，按稳定的来源 ID 保留最早记录。重抓、去重和快照重建沿用该值。严格触发归因要求发布时间和首次可见时间均不晚于触发。任一字段缺失时标记「触发时可见性未验证」，可在补充材料中查看。历史数据按原有版本保留，具备可靠来源记录时再补齐。

### P0-3 统一列表、详情和报告的归因口径

| 结构化状态 | 用户看到的文案 | 发布条件 |
|---|---|---|
| `confirmed` | 主因 | 公司催化符合现有证据等级和置信度门槛，且结论引用合格证据 |
| `hypothesis`，公司或其他候选 | 可能原因 | 有相关支持，因果关系仍待核实 |
| `hypothesis`，板块或大盘同向 | 板块联动待确认／大盘联动待确认 | 有可核验的同期联动，缺少直接传导证据 |
| `insufficient` | 证据不足 | 缺少有效主因支持，降级为低置信度并清除无支撑的主因链 |

触发行情证明异动发生，不能单独支持催化判断。即使公告能支持主因，也要对卖盘集中、资金抢筹等传导结论单独校验。缺少独立传导证据的节点标为推断，确定程度最多为「部分确立」。Worker 与 API 回写校验使用同一证据时间口径，前端和报告根据结构化状态映射文案。

### P0 验收用例

| 样本 | 回放时点，北京时间 | 通过条件 |
|---|---|---|
| 星帅尔 `002860` r2，+8.04% | 2026-11-04 14:49:40.266 | 保留触发行情，15:05 指数数据不进入模型输入和归因引用。有同期同向事实时显示联动待确认，缺少有效支持时显示证据不足 |
| 晶华微 `688130` r2，−10.38% | 2026-11-05 09:21:38.723 | 核实 08:45 公告首次可见时间。可证实触发前可见时允许纳入归因，无法证实时严格组排除。无独立卖盘证据的传导保持推断 |
| 同期行情缺失 | 任一有效触发 | 保留价格异动事实，缺失原因可查。报告不得以收盘数据回填盘中证据 |
| 主因仅引用触发报价或 T-1 行情 | 任一有效触发 | 回写结果和各端文案均降为证据不足 |

回放定位键分别为 `mv:002860:2026-11-04:1793773285176:up` 和 `mv:688130:2026-11-05:1793841668723:down`，两条都固定使用修订版 2。

### P0-4 明确「立即检测」的范围与反馈（评审提案）

现有按钮调用 `POST /api/cn/favorites/movements/detect`。接口强制执行一次检测，绕过交易时段限制，扫描范围来自全局自选股集合，并为当日活跃且缺归因任务的事件补入队。响应中的 `enqueued` 是归因入队数，页面据此弹提示并刷新列表。扫描与自动检测并发时可能被跳过，现有返回无法区分「未执行」和「执行后无异动」。

**建议定义**为「现在检查我的自选股是否出现价格异动」。操作需要登录，服务端从登录身份取得当前账号自选股范围。交易时段内按自动检测的同一套行情有效性、阈值和事件修订规则执行一次检查。命中后建立或更新事件，归因异步进行并复用已有任务的去重规则。App 和 H5 使用同一结果口径。

| 场景 | 预期行为与反馈 |
|---|---|
| 检查完成，有新异动或修订 | 刷新列表，按实际新建和更新数量提示。确有任务入队时显示「归因中」 |
| 检查完成，无新异动 | 提示「未发现新的价格异动」，历史卡片可继续查看 |
| 非交易时段 | 显示「休市中，可查看最近异动」。允许刷新已有结果，避免将旧行情记为新的盘中触发 |
| 无自选股 | 提示先添加自选股 |
| 正在检测或请求过于频繁 | 提示检测中或稍后重试，服务端对重复请求限频并复用在途任务 |
| 行情不可用或检测失败 | 明确提示失败或部分完成。对行情缺失的股票统计跳过数量 |

验收时用两个账号交叉验证扫描范围，覆盖并发点击、休市旧报价、无自选股及接口失败。手动检测、事件新建或修订、归因入队和归因完成分别反馈，避免用单一的入队数代替检测结果。休市策略和手动命中后的归因入队时机须在评审中确认。

## 3. P1 产品需求

| 编号 | 工作项 | 产品规则与验收 |
|---|---|---|
| P1-1 | 跨日催化关联 | 每天保留独立的价格事件。按同一股票与稳定的公告 ID、规范化原文链接或证据 ID 建立关联。匹配不明确时保留独立卡片。晶华微连续三天的卡片可逐日查看，同一催化标为「延续」，出现新证据时显示新增内容和时间。 |
| P1-2 | 离线回放入口 | 输入事件 ID、修订号和分析版本。固定模型、提示词及校验版本，对照原始快照与按时点筛选后的快照。输出排除原因、主因变化、置信度、证据引用和链路状态。先固化两条 r2，再跑全周 12 张卡，回放结果单独保存。 |
| P1-3 | 周度质量评估 | 分别统计同期行情覆盖率、首次可见时间覆盖率、归因完成率、无效引用率、降级比例、触发至出卡耗时，以及 App、H5 报告打开成功率。按数据缺失、队列失败、模型失败、发布拒绝和渲染失败归类。漏报率用同期行情回放检测器单独计算。 |

首周报告同时给出分子、分母和缺失样本。P1 的量化目标在获得基线后评审，避免用 12 张可见卡片估算全量任务成功率或漏报率。

## 4. 实施与发布门槛

| 阶段 | 交付内容 | 放行条件 |
|---|---|---|
| P0 本地联调 | Node 留存触发修订的指数证据，Worker 与 API 按时点校验，前端区分结论状态 | 类型检查和相关测试通过，完成两条 r2 的新代码回放，核对列表、详情及完整报告 |
| P0 数据补齐 | 接入带行情时间的板块分时，上游持久化消息首次可见时间 | 用真实采集记录核对时间语义、重试和缺失处理。验证晶华微公告的可见性，查不到时保留「未验证」 |
| P1 回放与关联 | 固化回放入口、全周样本和关联标签，产出周度指标 | 重跑全周样本并复核降级和误关联，确认各环节指标的统计分母 |

当前 P0 已有本地改动覆盖触发修订的指数留存、已知采集时间校验和列表状态区分。板块分时、可审计的消息首次入库字段，以及用新代码做真实数据端到端验收仍待完成。现有事件库采集时间可作近似记录，无法替代可审计的首次入库时间。

## 5. 待评审决策

- 行情数据负责人确认板块分时数据源、时间戳可信度和采集成本，并根据覆盖率评估 5 分钟窗口。
- 事件数据负责人确认首次可见时间的写入点、去重键以及历史数据能否核实。
- 产品与测试确认跨日关联的展示范围、灰度样本及首周指标目标。
